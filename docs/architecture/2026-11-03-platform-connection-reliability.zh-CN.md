# Android ↔ Core 连接与恢复职责

Platform 事件、Native Agent 会话和 HTTP 请求分别管理健康状态。登录成功不代表事件通道在线，某条消息生成结束也不代表同步通道关闭。现有 UI 文案保持不变，诊断必须记录失败来源。

## Platform WS/SSE

正式 WS：`GET /open-android-intelligence/v2/events/ws?cursor=<opaque>`。SSE：`GET /open-android-intelligence/v2/events?cursor=<opaque>`。两者使用相同设备认证、请求签名、会话续签和 TLS 身份校验，传送相同的持久事件。WS 优先；普通网络或升级不可用时使用 SSE。用户明确配置的 HTTP 仍按既有未加密提示处理；HTTPS 不因降级改为 HTTP。

WS 只有在 TLS、完整签名认证和 Upgrade 校验完成后才进入 LIVE。握手成功只证明连接已认证，不重置认证恢复次数；只有同一凭据下有效活动才可解除既有续签恢复栅栏。有效 Ping/Pong 和完整数据帧记录单调活动时间。握手保持短预算，已建立连接采用六十秒失活检测。解析失败、关闭码、认证拒绝和网络失败分别记录，不生成虚假业务事件或靠隐藏错误改变健康事实。

普通失败由 GatewayHttpClient 的现有事件循环恢复，退避按 1、2、5、10、20、40、60 秒并加入有界抖动。稳定运行六十秒后恢复初始退避。Runtime 持有一个正式事件流所有者；网络变化、凭据变化或明确重试交接时先取消并等待旧任务结束。

健康 SSE 期间允许 `GET /open-android-intelligence/v2/events/ws/probe` 探测。此入口采用相同认证和 TLS，客户端以控制 Ping/Pong 验证双向可达；无事件订阅、事件游标、在线计数或设备操作。单次预算十秒，失败按 1、2、5、10、15 分钟冷却并加抖动。SSE 不因探测失败中断。成功后先关闭探测、停止并等待 SSE，再从最后成功保存的游标建立正式 WS；失败回到 SSE。

旧 Core 返回不支持探测时继续使用 SSE，在正式事件连接失败或实际网络路径变化后重新尝试 WS。普通网络错误持续具备恢复能力；自然过期的有效会话使用 WS 关闭码 4001，进入既有受限续签；撤销或策略拒绝使用 1008。最终认证拒绝、设备授权撤销、证书/主机名/指纹错误暂停对应通道，不能靠换通道绕过身份。

## Native 与 HTTP

Native eventSync 继续使用各 Agent 的既有 Core 会话协议、分页、ACK 和不透明游标。正常长轮询 waitMs 为 25000，JSON HTTP 读取预算为 30000 毫秒，和 Platform SSE 空闲预算独立。

可恢复读/ACK 失败超过六次仍保持同步所有者、pending ACK 和持续退避；只有 Native 自身成功同步才报告恢复。connectionRestored 是合并唤醒，健康或正在恢复的读取不取消，不重建 synchronizer，不为每个 Platform 心跳刷新完整历史。认证、TLS、协议与本地保存错误分别处理。所有事件和回执核对账号、Agent、会话和 generation 归属。

HTTP Claim、结果上传和普通查询保留现有 API。HTTP 响应证明接口可达，但不能证明 Platform 或 Native 同步正常；401/403、网络不可达和 TLS 拒绝也不能混为同一事实。Core ↔ Session Adapter 继续原架构，手机观察连接关闭不代表 Agent 执行取消或结束。

## 生命周期与设备请求

应用进程拥有连接，界面只展示状态。重复网络可用通知、公网验证状态变化和普通前台恢复不重建健康连接；真正默认网络切换、路由变化或恢复唤醒由现有 Runtime 处理。局域网 Core 不要求公网验证通过。不增加仅为空闲保活的前台服务，沿用用户发起任务和 Android 后台执行限制。

设备事件先把 requestId 写入现有加密执行日志，再推进事件游标；HTTP 查询、Claim 和执行交给现有执行器。恢复时重读待查询通知、已领取检查点和已保存结果。同一 requestId 正在取消收尾时不启动新动作。执行和补传前继续检查期限、授权版本、提供者身份及现有授权栅栏。

结果上传失败仅补传已保存结果，不再次执行；已开始但无可验证结果时保持 outcome_unknown。过期、撤权或取消请求不能因重连再次执行。Core 的事件持久化、队列溢出断链重放、在线引用计数和风险分类继续生效；高风险即时请求不因普通离线恢复扩大期限。

## 诊断与验收

使用 GatewayWs、GatewaySse、GatewayEvents、OaiConnection、OaiNativeEvents、OaiDeviceRequest 关联通道、连接所有者、重建原因、关闭码、活动时间、失败次数、退避、游标摘要、revision 和 requestId 阶段。禁止记录凭据、签名原文、原始游标、用户消息、短信/通知正文或能力结果。

先按 requestId 确认 Agent 创建、Core 持久化、事件接收、查询、Claim、执行、上传和确认阶段，再判断故障源。测试结果分别记录自动化、本地模拟、CI、真实部署及 ADB 证据。Android 进程被杀或系统暂停网络期间不能保证实时投递，恢复后仍须按既有保留期限和授权补齐。

## 配套升级与回退

Core 与 Android 配套升级后支持无订阅探测及 4001 自然过期恢复。旧 Core 不支持探测时继续走 SSE，不能假称已验证主动恢复 WS。回退 Android 前，先用当前版本完成加密日志中 notified 阶段的远端查询与必要终态处理，确认不存在该新增阶段的待恢复记录，再停止写入、切回旧版。旧客户端不知道该阶段，不能把其清理行为当作可靠恢复。既有账号、主密钥、设备绑定、游标与历史不重建。
