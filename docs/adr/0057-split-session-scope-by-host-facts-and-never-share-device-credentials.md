# 会话接入范围按宿主事实二分，共享会话绝不继承设备凭据

原生会话的可见范围只有两种：Hermes 这类以账号密码建立会话身份的宿主强制 `account`
隔离；显式接入的 DSH 与 Codex 部署为 `deployment` 共享，部署内所有已认证账号看到
同一批真实会话。共享的只有会话可见性——任何账号的设备授权、配对与凭据都不随之共享。

为守住这条边界，Codex 适配器启动前检测子进程环境中是否出现 OAI 设备凭据
（默认客户端配置文件、调用 `oai`/`oai_core.cli`/`oai_core.mcp` 的 MCP server、
`OAI_` 前缀凭据变量），命中即拒绝启动；模型提供方凭据只能经 `envFrom` 显式映射，
子进程环境不继承 Core 的完整环境。共享会话可影响同一宿主执行的命令，把某个账号的
设备凭据放进共享宿主进程等于把该账号的设备能力交给全部会话参与者，这是本次拒绝
默认继承的动机；宿主侧会话桥令牌也仅作 Core↔宿主内部认证，不是设备凭据。
