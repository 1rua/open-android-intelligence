# Android 安装实例是设备能力授权的唯一权威

同一手机连接不同 Core、账号或 Agent 时需要保持相同的本地能力策略。2026-11-01 的
[全局授权规格](../superpowers/specs/2026-11-01-global-device-authorization.md)取代本 ADR 旧版的配对范围能力限制、
旧许可迁移复核和启用即自动执行规则；实现与验收状态见[执行记录](../reviews/2026-11-01-global-device-authorization.zh-CN.md)。
此前报告仅保留历史证据价值，不代表当前新模型已实现。

## 决策与边界

设备能力策略属于 Android 客户端安装实例。每项能力独立总开关与每次手动、允许只读、自动允许三种模式；
新能力默认每次手动，主动推送默认关闭。插件安装/启用、系统权限、本地数据范围和系统强制同意均独立生效。
切 Core、账号、Agent、断网或进程重启不能重置持久策略；全账号退出暂停采集、执行与推送，保留配置和有效加密队列。

Core 负责认证、设备访问关系和传输绑定、协议校验、发现、路由、请求生命周期及 ACK；不存储另一套能力许可，
不使用旧账号 grant 否决 Android。所有合法设备调用通过统一 CLI/API/MCP，声明 Agent 名称和操作目的供展示审计，
这些声明不证明身份。调用凭据必须仍绑定可访问的目标设备；私有会话、附件、历史继续按账号隔离。

临时许可由 App 绑定能力、操作类型与已批准数据范围，在所有合法 Core/账号/Agent 请求间共享。
最长确认等待 5 分钟；仅本次和 5/30/60 分钟批准均支持撤销，取消、到期、参数越界和重启不能扩大许可。
最终副作用及敏感结果交付前重新核实当前许可。

短信与通知被动范围、主动推送范围独立。推送只到用户选择的可验证稳定路由端点；App 持有唯一长期敏感内容加密队列，
逐端点 ACK、去重、到期和撤销清理；Core 仅保留可靠路由需要的最小状态。屏幕读与控制分别授权，控制使用必要的 FIFO 独占租约。

## 迁移与取舍

按 Core/账号/配对保存的能力许可与其旧迁移标记退出裁决，幂等迁移到安装实例策略；不能清除系统已授权限、
登录、账号、主密钥、设备密钥、会话、附件或插件安装记录。旧敏感在途请求失效，不因迁移或重试恢复执行。
已明确的本地关闭继续保留，旧服务端许可不转换成新自动许可；没有全局策略的能力采用每次手动。

全局共享降低重复授权成本，代价是必须明确区分设备访问关系与账号私有会话范围，避免把跨账号设备调用解释成会话互通。
Android 平台的 Runtime Permission、Notification Listener、Accessibility、MediaProjection 与后台限制保持其系统边界。
现有 `android-v1` 协商和封闭 Schema 需按实际变更兼容检查，不以文档预先宣称线协议无需变动。

## 2026-11-01 范围与升级约束补充

短信范围增加全部、关键词和电话号码后，新配置默认全部，但推送总开关仍关闭；旧明确限制和未确认队列不得因默认变化扩大。关键词可在本机正文上判定，是否向调用者提供正文由独立开关控制。通知继续使用原应用列表的搜索、正选和反选；详见规格 UI-01 至 UI-06。

不认识新范围的旧程序必须拒绝读取新授权模型，不能忽略关键词字段而退回全部。授权持久模型与主动队列均升级版本，读取旧数据时保留范围、正文、稳定事件身份、逐端收据、游标与原到期时间；未知版本或损坏继续停止敏感执行。该版本屏障用于防止降级扩权，不能通过重建身份、密钥或清空数据绕过。
