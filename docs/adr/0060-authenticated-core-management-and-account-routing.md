# Core 管理须认证，账号登录与设备路由分离

Core 的全局管理操作必须验证现有 Core 管理员及其 Core 密码；系统用户、root、本机确认或会话桥凭据不能代替。全新部署受控引导首位管理员，旧部署指定并验证现有账号；删除或降权不得移除最后一位可用管理员，安全改密不要求先另建管理员。管理员本机恢复使用预先登记的独立一次性恢复码，不代替普通账号的二次验证备用码，也不授予读取他人设备或会话的权限。

服务端 2FA 默认关闭，仅在管理员完成验证器和恢复准备后按需开启；开启后登录与管理验证第二因素，有效会话正常续期不反复要求验证码。这样在不增加默认使用门槛的同时允许部署选择更强保护，代价是需要妥善保管互相独立的恢复材料。

CLI/MCP 先认证账号，不要求登录时选择设备。一次设备调用依次选择显式目标、可信会话来源、有效默认设备、唯一在线设备；前三者离线时按风险排队或拒绝，不改投，多个在线设备则要求用户选择。已接受的请求及其幂等重试始终保留原目标；旧设备限定凭据仍保持原限制，不因迁移自动扩权。设备配对、签名和 Android 最终授权不变。

Agent 候选可从当前安装用户的受支持位置或明确授权目录有限发现；候选不是已连接实例，仍须验证身份、真实握手和确认注册，不遍历其他用户目录或执行未知脚本。此决定取代 [ADR-0058](0058-config-is-the-agent-discovery-boundary.md) 的“仅显式配置才可发现”限制，但保留真实在线探测；[ADR-0057](0057-split-session-scope-by-host-facts-and-never-share-device-credentials.md) 的账号隔离和共享会话不继承个人设备凭据仍然有效。Hermes 自动专属空间、安装路径和 Android 真机端到端结果以实际集成及验收记录为准，本决策不代表已验证通过。
