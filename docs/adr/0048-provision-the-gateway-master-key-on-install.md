# 安装插件时自动预置受限主密钥文件

ADR 0023 要求主密钥优先来自宿主秘密存储，没有时由部署者提供权限受限的专用密钥文件，并在密钥来源缺失或权限不安全时拒绝启动。Hermes 的 `PluginContext` 并不提供秘密存储，而实现此前只是把这种情况静默降级为空主密钥，于是"宿主没有密钥接口"被伪装成"密码登录成功、但每个已认证请求都返回 400"：设备公钥与签名都正确，用户却无法上传附件或发送消息，且日志里没有一行可归因的失败。本 ADR 细化了 ADR 0023 的落地方式，不改变其安全属性。

现在把"提供密钥来源"这一动作绑定到安装插件本身，而不是要求额外的密钥创建步骤。加载插件时，宿主秘密存储不存在就在默认路径 `~/.open-android-intelligence/gateway-master-key` 生成 32 字节随机密钥，文件权限固定 0600；仅当该目录由本次调用创建时才把目录收紧到 0700，避免改动部署者指定的既有目录。部署者可以用 `OPEN_ANDROID_INTELLIGENCE_GATEWAY_MASTER_KEY_FILE`（兼容别名 `OPEN_ANDROID_GATEWAY_MASTER_KEY_FILE`）覆盖路径，也可以用 `./hermes-account.py init-key` 显式生成；`init-key` 与自动路径都绝不覆盖已存在文件，因此重复启动不会轮换正在保护线上数据的密钥。密钥文件位于 Hermes 数据目录之外，不随数据库、备份或诊断一起导出，每个账号再用 HKDF-SHA256 从该文件派生独立密钥，保持 ADR 0030 要求的账号间密钥隔离；加密为 AES-256-GCM，用途字符串作为附加认证数据。

"缺失即拒绝启动"的约束按"不安全的既有来源"保留，而不是按"文件尚未生成"保留：路径存在符号链接、不属于当前用户、组或其他用户可读、内容长度不合法、或目录不可写导致无法生成时，平台拒绝启动并在日志中给出一条可操作的原因，绝不退回到无密钥运行。这样默认部署只需安装插件并通过 `hermes gateway setup` 创建账号密码，即可在手机上配对使用；一旦运算符提供了不安全的密钥文件，失败仍然立刻且可见。

自动生成发生在账号创建之前，因此新账号从一开始就带着有效的主密钥引用；对 ADR 0023 时期遗留的空 `master_key_ref`，首次以真实密钥打开账号时会就地升级为该引用，不会报 `MASTER_KEY_REFERENCE_MISMATCH`，因为这些账号的暂存区与数据库里没有任何以其为密钥的数据。
