# 保留独立发送身份并以防抖批次聚合 Agent 输入

> **2026-11-13 目标范围**：客户端发送原子和已由 ADR-0062 修订的消息合并行为保留；旧 Gateway wire 格式与路由不移植到 Remote。 见[新总规格](../specs/2026-11-13-dsh-remote-architecture-refactor.md)。本次仅确认目标，不宣称运行时代码已变更。

> 2026-11-10 修订：防抖窗口改为纯客户端配置（默认 0 秒、0～30 秒、不按 Core 覆盖）。
> 本文其余约束继续有效，详见 [ADR-0062](0062-own-message-merging-in-the-android-client.md)。

Android 为每次用户明确点击发送保留独立本地发送单元及其稳定 `clientMessageId`、已分配的远端 `messageId`、顺序和状态；待补充协商、Schema 与一致性向量的版本化 `message-batches` 扩展，以 `clientBatchId` 原子提交同一 Gateway 和对话线程内的普通文本成员，并只向 Agent 交付按 `newline-v1` 连接的一次有序输入，聚合不合并成员身份或状态。Gateway 只保存可靠交付所需的成员映射、幂等元数据和短期正文，长期历史仍属于 Agent 宿主。普通文本防抖全局默认可按 Gateway 覆盖，时长 `0–10` 秒且默认 `1.5` 秒，后续消息默认延长窗口，单批最多二十条、总字节不超过协议协商的批次上限、从首条起最长等待三十秒；任何斜杠命令或含附件的发送单元都是硬边界，设置变化只影响新批次。每个对话线程只允许一个 Agent 生成运行，聚合批次按 FIFO 等待，`/new` 由 Agent 命令入口立即创建新线程而不取消旧线程生成；生成使用独立且不透明、不同于配对和连接 generation 的 `generationId`，并通过独立幂等操作取消，在线短暂失败只能使用相同请求、批次和成员身份重试，进程重启后未获得明确终态的批次必须由用户重新确认并先核对是否已经送达。
