# 将原生屏幕控制与 WASM 离散数据能力分离

WASM 继续承载短信、通知、通话记录等离散数据能力与脱敏处理；屏幕节点遍历、图像编码、连续手势
和动作后收敛由 Kotlin 端口负责。当前屏幕 WASM 包只是原生 primitive 的薄包装，重构复用实际
Kotlin 后端并移出高频包装路径，不将已有驱动误认成需要从 WASM 重写。
两种能力都须经过平台内核；原生端口不是受保护模式的权限旁路。

手机默认返回精简语义树，按需提供有快照绑定的 SoM WebP；不能对图像界面编造不存在的可验证控件。
动作后等待连续 400ms 静默或 3000ms 硬超时，分别报告动作执行与界面收敛结果，超时不得自动重复动作。
具体目标绑定、文件与回执见[控制契约](../contracts/oai-control-rpc-v1.md)。

## 取舍

统一经 WASM 包装能够沿用插件调用形状，但会将高频屏幕状态和动作生命周期塞入离散插件通道。
选择原生端口可利用真实 AccessibilityService 事件、手势回调和窗口生命周期，代价是需要把
本机策略、租约、防重、审计和取消明确接到这些原生入口，不能仅删除插件包装后直接调用系统 API。

本机确认、实时状态和紧急停止改由 TYPE_ACCESSIBILITY_OVERLAY 承载，避免拉起主 Activity 改变
第三方应用焦点。代价是要处理悬浮窗本身的事件、目标复核和远程自我确认拦截；保留原有窗口变化校验，
不能以“排除悬浮窗”为由忽略真实目标变化。悬浮窗也不构成永久保活保证。

## 授权边界

沿用 ADR-0059 的安装实例权威：新能力默认每次手动，选择允许只读后批准范围内读取免逐次确认；
敏感操作无论其他模式如何均须本机确认。屏幕读、截图、控制和后台数据许可分别生效，
锁屏拒绝全部屏幕请求。可选 Shizuku 引擎须显式可用和授权，不因失败自动提升权限。
完整行为与验收见[总规格](../specs/2026-11-13-dsh-remote-architecture-refactor.md)。
