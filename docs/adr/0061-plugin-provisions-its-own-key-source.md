# 插件自带主密钥来源，加载不再依赖人工准备

> **2026-11-13 目标范围**：本文旧服务插件的主密钥供应流程随该服务退役，不作为 Remote 登录前置；插件作者身份与手机本机加密仍分别由其现行边界负责。 见[新总规格](../specs/2026-11-13-dsh-remote-architecture-refactor.md)。本次仅确认目标，不宣称运行时代码已变更。

ADR 0048 把"提供密钥来源"绑到安装插件上，但实现仍有两处把"文件尚未生成"当成"部署不可用"：`hermes gateway` 加载插件时构造函数直接读默认路径，文件不存在就抛 `MasterKeyUnavailable`，插件被宿主忽略；错误文案还让用户去执行插件仓的 `./hermes-account.py init-key`，而该脚本在 Core 独立化之后已不在运行路径上。结果是文档声称的"装完即用"在真实宿主里仍卡在人工建密钥这一步。

本 ADR 明确三条边界。

**一、缺失即生成，只有"不安全的既有来源"才拒绝启动。** `resolve_local_master_key_store()` 在没有任何密钥文件时自动在首个可写位置生成 32 字节随机密钥（`0600`，目录仅在本次创建时收紧到 `0700`）：显式配置的 `OPEN_ANDROID_INTELLIGENCE_GATEWAY_MASTER_KEY_FILE`（及其别名）优先；未配置时依次考虑调用方指定的专用路径、历史默认路径 `~/.open-android-intelligence/gateway-master-key`、以及 `XDG_STATE_HOME` 下的同目录。符号链接、非本人所有、组或其他用户可读写、长度不合法仍然立即失败，绝不"修复"或覆盖运维人员放错的文件——那会让正在保护线上数据的密钥被悄悄换掉。

**二、全部位置都不可写时降级为进程内临时密钥，而不是阻塞宿主。** 插件加载失败会让用户完全看不到这个平台，连配置入口都没有；而临时密钥至少让会话桥可用，并在日志里明确写出"重启后新建数据无法解密、请修正目录权限"。因此降级只发生在"写不进去"这一种情况下，绝不发生在"文件已存在但不安全"的情况下。

**三、会话宿主在新建部署中使用自己的密钥，不复用设备 Core 的密钥。** Hermes 只是会话宿主，不持有设备能力，也不需要设备加密密钥。全新部署中 `SessionBackend` 未注入密钥时使用 `~/.open-android-intelligence/session-master-key`，与 Core 的 `gateway-master-key` 分离，并且都不落在各自的 home 或账号目录里，备份宿主数据不会连同密钥一起被带走。但**既有文件优先于新建文件**：老版本 Hermes 适配器用的是默认路径 `gateway-master-key`，若该文件已存在而专用会话密钥尚不存在，则继续使用既有文件，否则已经写入的原生会话内容会在下次启动时无法解密。若运维人员显式配置了环境变量路径，则始终只使用那一个来源，避免"文件后来出现导致密钥悄悄切换"。

同一批修复还包含两项配套改动：

- **平台注册与配置探测分离。** `register()` 只做无副作用的参数读取，即使 `OAI_HERMES_*` 尚未填写也注册成功；平台通过 `is_connected` 报告 `configured` / `not configured`，并声明 `required_env`，因此 `hermes gateway setup` 能列出该平台并提示缺哪几个变量。真正的账号目录与密钥初始化推迟到工厂第一次被调用时，那里才报告具体的配置错误。
- **MCP 依赖上限解除。** `oai-core` 原先声明 `mcp>=1.20,<2`，而 Hermes 的 `mcp` extra 以及系统全局包已经使用 `mcp 2.x`，插件安装时依赖树无法同时满足，被宿主安装器判定为冲突而拒绝。Core 的 MCP 模块改为单一兼容层：1.x 走 `mcp.server.fastmcp.FastMCP`，2.x 走 `mcp.server.MCPServer`（两者的 `tool()` / `run()` 表面一致），并把可预期的领域错误转成 SDK 自己的 `ToolError`，以保留 2.x 才有的错误文案透传。依赖声明随之放宽为 `mcp>=1.20`。

验证：新增 `oai-core/tests/test_agent_plugin_zero_config.py` 覆盖自动生成、既有密钥不被轮换、专用会话密钥与 Core 密钥分离、显式路径唯一性、不安全文件失败关闭、不可写时降级为临时密钥、未配置时平台仍注册且报告未配置、配置完成后报告已配置并生成会话密钥；并在本地以 `mcp 1.30` 与 `mcp 2.3` 两套运行时分别确认工具列表与错误文案一致。真实 Hermes 宿主与真实系统的 `mcp 2.x` 安装仍需按其版本单独验收。
