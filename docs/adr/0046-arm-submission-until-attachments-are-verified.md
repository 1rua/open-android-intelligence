# 以冻结附件快照和一次性待提交意图发送消息

> **2026-11-13 目标范围**：附件就绪后才提交与用户明确发送的原则保留；旧 Gateway 上传/发送接口由 Remote 真实附件能力替代，不迁移旧数据。 见[新总规格](../specs/2026-11-13-dsh-remote-architecture-refactor.md)。本次只更新文档，不宣称运行时代码已变更。

附件选择后可以立即预上传，用户在附件尚未全部 `verified` 时点击提交只在 Android 本地冻结文字与有序附件快照、建立一次性待提交意图和稳定消息身份；Gateway 仍只在全部附件验证后接收消息，并且同一意图恰好发送一次。任一附件失败都会阻止整条消息，重试成功可继续原意图，移除、替换、新增或编辑则使原意图失效并要求重新提交；等待阶段可以取消并保留草稿，普通附件使用按账号与 Gateway 隔离的加密临时暂存支持重启后手动重试，已明确失败或过期的远端附件尝试作废并创建新尝试，屏幕选区附件仍不跨助理会话恢复。正文可以是显式空字符串但附件数组必须非空，空正文且无附件的消息无效；后端必须提供附件状态查询、未被消息引用附件的幂等删除和按 `clientMessageId` 查询消息结果，客户端对创建、上传、提交和消息发送分别保留稳定请求身份，未知结果不得猜测为失败或重复提交。
