# 通知采集白名单应用选择

通知采集设置的白名单入口改为选择本机已安装应用，用户无需查找或输入包名。通知采集权限、字段范围与投递模式继续使用原有策略端口。

## 交互

- 设置页以应用名称和包名展示已保存的白名单，提供「选择应用」和逐项移除入口。
- 选择页使用 Material 3 列表与复选框，展示图标、应用名称和包名，支持按名称或包名搜索、多选。
- 进入选择页时按已保存白名单预选。勾选只编辑草稿；点击「保存」且策略端口接受后才生效。关闭或系统返回会放弃草稿。
- 未选择任何应用表示不采集任何通知；不默认全选。
- 旧白名单中已卸载或当前不可见的包名保留，并标明状态，允许用户取消；应用查询不得静默清空已有策略。
- 加载期间展示真实进度；查询失败展示错误与重试，不能伪装为空列表。每次回到前台重新查询，反映安装与卸载。
- 系统重建界面时保留选择草稿、搜索词和打开时的策略版本。

## 平台与分发边界

应用列表通过 Android `PackageManager.getInstalledApplications(0)` 查询，在后台线程读取；应用身份始终是包名。同名应用不合并，重复结果按包名去重，应用名称按当前语言排序。枚举后应用被卸载时跳过该项。

Full 变体单独声明 `QUERY_ALL_PACKAGES`，以覆盖没有桌面入口但能发送通知的应用。主清单声明 `MAIN` + `LAUNCHER` 的查询范围，Play 变体保留系统过滤后的可见范围，并在选择页提示。这里只查询当前 Android 用户可见的应用，不跨工作资料或 Android 用户读取。

Android 的应用列表可见性依据：[应用可见性](https://developer.android.com/training/package-visibility)、[声明应用查询范围](https://developer.android.com/training/package-visibility/declaring)。

## 策略边界

遵循 ADR 0050，App 仅通过 `NotificationPolicyPort` 保存 `packageIds`，不导入采集器，不改变存储格式，不新增授权账本。选择应用不授予系统通知使用权、本地采集同意或 Gateway 插件配对权限。

批量保存携带进入选择页时的 `expectedRevision`。若策略已经被其他操作更新，保留未保存草稿并显示拒绝原因；用户可重新载入权威端口中的选择再保存，禁止拿最新版本号强行覆盖旧草稿。

## 验证

- Robolectric 查询测试覆盖真实包管理器状态、图标与名称、无桌面入口、同名应用、当前语言排序、卸载与重复查询，以及 Full/Play 权限差异。
- Compose 界面测试覆盖多选保存、取消、按名称/包名搜索、旧项保留与显式清空、错误重试、空列表和并发更新冲突。
- 本机运行定向测试与通知装配/架构守卫；完整构建与完整测试交由 GitHub Actions，真机应用列表与通知行为由用户验收。
