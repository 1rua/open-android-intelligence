# 本地会话、持久附件与下载实施规格

本规格落实用户批准的 Android、Hermes、OpenClaw 联合修复，依总架构、ADR 0053 和 Gateway Protocol v2 实施。长期跨设备内容权威仍属于 Agent 宿主，Android 保存可离线阅读的本地副本。

## 用户行为

- 已同步会话先显示本地保存的用户与 Agent 消息，再后台更新；不能先把仅发送记录当作已恢复的完整历史。
- 默认保存双方附件原件与元数据，第一次打开旧会话时补存仍可读取的原件；已经保存的原件不重复从网络获取。
- 原件持续保留，不自动淘汰；空间不足或来源消失明确提示，纯附件消息始终使用附件卡片。
- 用户点击下载后将普通文件保存到系统 Download/OpenAndroidIntelligence，原始文件名净化后交给平台避让同名。

## 本地持久化与迁移

镜像按 profile、Gateway、账号、安装实例隔离，数据库和原件位于 noBackupFilesDir。SQLite 保存查找摘要、资源类型、版本、删除标记与密文；AAD 绑定范围、资源身份及版本。正文、发送身份、草稿、批次、附件身份与完整性信息保持可恢复。

本地读取、加密及提交在 IO 线程执行。发送前等待发送事实和检查点落盘；消息更新、删除事实与对话事件游标事务提交后才确认事件。远端完整分页快照按消息修订合并，迟到旧页和无明确删除的空页不能抹掉新回复。

旧文档先验证，再一次性事务导入；失败不重置账号或清空旧数据。已迁移路径停止写入，旧密文移入专属复核目录。原件独立使用无 TTL 的分块文件，旧媒体成功导入并验证后才退休原副本。明确删除取消相关未完成任务，迟到结果不得重新发布；私有清理不修改用户公开下载。

## 读取与下载接口

媒体端口提供本地元数据、补存、发送原件归档和可关闭的原件流。控制器按不可变的账号、会话和附件身份启动任务，下载通过独立端口执行；未接真实端口时显示真实不可用状态。

历史媒体支持签名参数 format=stream-v1，具体字段、授权和错误规则见 Gateway Protocol v2。Android 根据明确的格式响应头消费原始流，旧 JSON/Base64 只走有界兼容分支。不得把 JSON 附件当作协议外壳，不以扩大整体内存限制替代流式读取。

MediaStore 写入使用 pending 状态，核验长度和 SHA-256 后发布。进程中断通过账号私有日志恢复；主动取消持久标记取消并安全回收，不在下次登录重新发布。恢复失败保留日志，不能阻止正常会话登录。已公开条目属于用户，不再次改写或删除。

## 验收与发布

必测：网络阻塞下的双方首屏、进程恢复、旧页/低修订覆盖、完整分页、纯附件、超过旧 8/25/32 MiB 的原件、断网导出、同名文件、空间不足、取消与中断、删除竞态、旧数据迁移和账号范围隔离。

自动化源码、真实 HTTP、真实 Android MediaStore、完整 CI 与已部署手机分别记录，不能互相代替。测试通过后才提交推送；三仓代码版本、SDK 版本和契约必须固定并复核。新增附件事件 Schema 改变核心摘要，App 与插件必须使用相同核心 Schema 版本升级，单端升级会被 PROTOCOL_INCOMPATIBLE 拒绝。
