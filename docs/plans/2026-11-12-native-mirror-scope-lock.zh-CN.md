# DSH 队列恢复的同库镜像事务协调

关联 Issue：#142。固定基线：`83fbef075a494f0d4899cc22c08b4864c9edb3cd`。

原隔离模拟器真实 Core 重启场景已捕获 `SqliteConversationRecords.transaction:116` 的 `IOException`，cause 为 `SQLiteDatabaseLockedException`。两条消息各执行一次且历史稳定，但 checkpoint 失败后恢复，不能通过验收。

## 本轮范围

1. 先以真实 SQLite 双句柄协调 checkpoint 与仓储事件提交，建立可控锁竞争红环。
2. 根据红环选择最小同数据库事务协调；覆盖不同实例及 scope，确认锁顺序和资源释放，不吞掉异常、不加无条件重试。
3. 回归验证失败真实传播、关闭重开、同库与异库并发；保持既有消息身份、队列、加密与持久事务语义。
4. 独立 Standards / Spec 审查后按相关门禁合并，再在保留原账号/密钥/会话的用户10执行真实 TCP、Core/DSH 重启验收；从起始时间检查全部保存阶段日志。

## 完成条件

- [ ] 实际竞争根因有稳定红环，修复前红、修复后绿。
- [ ] 无数据库锁异常、无死锁、失败资源正确释放，异 scope 保持独立。
- [ ] 独立评审与必要自动化通过。
- [ ] 原隔离模拟器完整复测通过，最终状态与全过程均无保存失败。
