# 内置 DSH 适配器兼容性修复

## 目标与范围

从 `dev` 固定基线 `24172841f9a564c53416f7d066f3450d4feb2bfe` 修复内置 DSH 适配器的真实宿主参数契约、超长会话摘要以及历史客户端身份关联，关联 OAI #141、#142 和独立 DSH #4、#6。活动生成恢复和精确取消先以真实宿主 API 及跨仓库契约为依据对齐，再补齐实现与回归。

独立插件与内置适配器各自交付，保留 Core 的账号、设备授权及路由职责。本分支不部署真实服务，不访问用户模型凭据或私有会话，不将替身测试当成真实模型或设备端到端验收。

## 实施顺序

1. 用要求有效 `AbortSignal` 的入口及已安装 DSH `0.2.2-rc.1` 的真实方法建立失败回归；修复 `prompt(request, signal)`，信号生命周期独立于 HTTP 观察连接。
2. 用十五万条合成事件复现摘要参数展开失败；改为迭代求最大时间，保留混合正常与长会话的完整列表。
3. 保留历史用户消息的原生 `source.rpcId`，输出可验证的 `clientMessageId`，不按正文或时间猜测关联。
4. 研究真实权威活动状态、持久轮次事件和同步 `Agent.cancel`；比较目标轮次与调用取消之间不得发生异步切换。与独立桥及 Core 对齐路由、标识与终态，再实现 #142 范围。
