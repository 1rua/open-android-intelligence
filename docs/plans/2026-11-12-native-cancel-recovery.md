# DSH 取消终帧的权威恢复修复计划

关联 #179、#180，归入 #142 的异常恢复验收。基线为 `2caabfb1206fd93cd0232171f0bf287fdfeea498`。

## 已确认的问题与复现

真实 DSH 重启现场中，首轮已权威取消，但未投递后继仍排队，平台 LIVE、仓储 FAILED，且没有恢复所有者。隔离受控探针使用真实 AgentSessionClient 与 CoreAgentConversationRepository、合成传输，发现 `error/CANCELLED` 终帧绕过按原身份的恢复流程：仓储进入 FAILED，建立未知屏障并移除 turn；重复 connectionRestored 不会查询该 client。对照 `done/cancelled` 可自动排空；显式 retry 在安全 currentGeneration 查询为 null 后才排空。未知结果对照继续保留屏障，不重复提交。

## 最小修改范围

1. 将宿主 `CANCELLED` 错误终帧纳入既有按原身份的权威恢复路径，查询实际 generation/历史后再投影取消事实，不直接伪造完成或空闲。
2. 增加正式回归：error/CANCELLED 后权威取消、后继一次发送；查询失败/仍运行/未知不越屏障；多会话/Agent 和取消轮次隔离。
3. 若受控证据只需上述入口修复，不增加无条件重连重试或重复队列驱动。#180 与 #179 属同一现场候选链路，应按证据确认是否同根因。
4. 聚焦测试、独立 Standards/Spec 审查、PR 门禁后合并，再用保留数据的 AVD 完整副本和真实 Core/DSH/现有专用模型验证。最终同一提交 Full 成功前保留总跟踪开放。

## 禁止改变的行为

保留原 `clientMessageId`、权威 cancelled 和错误传播；不清未知屏障、不换 ID 重投未知输入、不取消非目标任务；不修改账号、密钥、原生历史或设备授权。此任务不扩展 DSH 桥职责。

- [ ] 错误/运行中/未知查询、取消竞态、多会话和资源释放回归通过。

- [ ] 最终副本用户10的 DSH 重启真实验收与同一提交 Full 通过；结果分别记录，未完成不伪报。
