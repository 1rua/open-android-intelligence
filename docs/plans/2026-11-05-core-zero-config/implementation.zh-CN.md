# OAI Core 零配置与管理员认证重构

## Context

用户应当登录一次 OAI Core，就能发现和调用本人设备；换手机、重新配对、Agent 登录不应再要求逐项修改服务端配置。同时，用户管理、安装升级、全局配置和修复必须验证 Core 管理员身份，不能把本机用户或 root 当成管理员。

本次只读审查基于 `dev@f5bd4bd6`，源码未改，安装、构建、测试及真机操作均未执行。批准后在仓库内 `.worktrees/` 创建 `feature/oai-core-zero-config-admin-auth` 开发，最终中文提交并创建面向 `dev` 的 PR，不自动合并或修改真实部署。

## 已确认的规则

1. **旧部署首管理员**：在受保护本机迁移中，现场指定现有账号、验证原密码并确认；仅该账号获得管理员角色，其他旧账号为普通用户。
2. **2FA 默认关闭，由服务端开启**：关闭时保持密码登录；开启时 CLI、Android、管理与恢复执行二次验证。有效会话正常续期不反复问码。
3. **离线不自动改投**：显式设备、可信会话来源或有效默认设备选定后，离线也按原风险规则排队/拒绝。没有这些目标时才选择唯一在线设备；已撤销默认记录失效，普通历史离线记录不制造歧义。
4. 保留 Android 最终授权、设备签名、账号/附件隔离和原有交互；保留 Hermes 账号隔离、DSH/Codex 既有部署共享语义，绝不把共享会话解释成共享个人设备凭据。
5. 保留现有 CLI 的状态、取消、ACK、推送端点、MCP、skill 等能力；不借“极简”删掉必要的调用声明、幂等和等待行为，不改无关 UI 文案或布局。

## 只读审查依据

| 现状 | 改造应复用的实现 |
| --- | --- |
| CLI、`gateway.admin`、配置 helper 三条写链没有统一管理员认证；`localConfirmation` 不是身份验证 | `gateway/credentials.py` 的 scrypt、`AuditStore.scrub`、现有主密钥保护 |
| `auth.py` 的 Token/Principal 绑定设备，`device_service.py` 的幂等键还包含设备 | 现有设备队列、Claim/Result/ACK、请求及结果状态机 |
| Android 已上报安装 ID、名称和公钥，但密码登录每次创建新设备 ID | `GatewayRuntime`、`GatewayAuthClient`、持久账号绑定和设备密钥 |
| 改密只撤 Android refresh，没有统一撤销 Core Token 与现有 access | Android 已有续期合并、刷新 journal 和本地退出屏障 |
| `endpoints.py` 用短 Token 摘要作为端点所有者，附件和 Hermes 来源也依赖旧 Principal | 既有稳定推送路由、逐端 ACK、附件设备归属和 trusted_turn |
| 安装先更新源码/依赖再配置；helper 经普通环境变量接收密码 | `scripts/core_setup.py` 的锁、候选、备份、journal、摘要、fsync、原子替换及移动保留回滚 |
| Agent 运行时只发现显式配置，Hermes 要手工映射 | `SessionAdapter`、注册工厂、entry points、真实 `status()` 和别名冲突检查 |
| `create_core()` 会补密钥，`open_gateway_account()` 会初始化/迁移 | 必须新增真正只读的认证入口，不直接调用上述写入路径验密 |

## 推荐架构

规则收拢为三个有明确 Interface 的 Module，Shell/CLI/MCP/Adapter 只负责输入输出：

- **账号与安全**：账号、密码、角色、登录/管理会话、2FA、撤销和恢复，在线离线共用。
- **设备访问与路由**：从已认证账号和可信来源选首次目标，持久化后不再重选。
- **Agent 注册与关联**：有限发现、验证实例、确认关联，按既有宿主范围访问会话。

新增文件拟为 `oai-core/src/oai_core/{identity,management,mfa,instance,routing,agent_registration}.py`。现有配置事务实现移入可安装的 `configuration.py`，`scripts/core_setup.py` 保留薄兼容入口及原回归；不另造事务或只有转发作用的抽象。

### A. 统一身份、撤销与隔离

- 实例安全 SQLite 放在受保护的 `runtime/security/`（目录 0700、文件 0600），集中保存登录名→稳定 accountId、原格式密码摘要、角色/状态、认证版本、2FA、登录/管理授权、恢复证明、Agent 关联和独立管理审计。
- 原 scrypt 摘要直接迁移，不要求重设密码；迁移后安全库为唯一认证权威，`CredentialStore` 兼容 Interface 转交统一实现，旧表只留不可登录的历史标记并阻止旧写入者。生产装配缺身份库即拒绝，不回退旧摘要或测试验证器。
- 旧账号 ID、目录、主密钥及线协议身份不重建；新账号生成稳定 opaque ID，登录名不再充当隔离主键。修正密码入口的 `username == accountId` 假设。同名删除重建不能继承旧设备、请求或 Agent 关联。
- 设备、内容和附件仍在各账号私有库；Hermes 原生账号/会话库不并入 Core 安全库，二者只保存已确认关联。
- 普通 Principal 表达账号与稳定登录会话；Android `VerifiedRequestContext` 继续要求完整签名身份；请求目标用独立不可变绑定，不把设备字段全部改成可空以绕过检查。
- 改密、停用/删除、角色或 2FA 安全变更、恢复，在安全库同一事务内更新版本、撤销登录/管理授权并写审计。Android access/refresh、旧 Token、长连接、推送和结果交付都检查当前权威版本，不能等后台清理才失效。
- 普通改密保留设备公钥，但旧设备不得仅凭原私钥绕过新的账号认证或 2FA。设备解绑只撤对应配对、Android 登录和请求，不撤账号级 Agent/CLI 登录。
- 最后管理员保护在实例锁/事务内执行，检查启用状态、有效密码及当前策略下可完成认证的因素/恢复证明，不只数角色。删除先撤销、确认、再移动保留，不新增永久删除。

### B. 管理认证、引导与本机恢复

- 使用受保护本机管理层，不新增公网管理端口。所有全局写入口验证现有管理员密码；服务端开启 2FA 后再验证第二因素。普通登录、设备签名、桥令牌、root 或 `--confirm-local` 不能代替。
- 单次管理命令现场认证；setup 内可复用默认 15 分钟、不可无限续期的管理会话。随机 handle 由验证方保存摘要，绑定实例、账号版本、动作范围和期限；每次动作/提交重新验权，时钟回拨不能延长期限。
- 密码/OTP/恢复码/管理凭据经隐藏终端、内存或继承文件描述符传递，不进 argv、普通 env、日志、Shell 历史或普通临时文件。helper 验证真实授权，不信任调用者的“已认证”标志。
- 内部桥凭据改用受保护 secret 引用/文件描述符，旧 `tokenEnv` 或内联值仅用于兼容迁移读取，确认后迁移，不静默轮换。
- **全新部署**：锁内确认无账号、历史安全状态及未完成事务，通过受控终端/FD 持有的一次性证明引导首管理员；证明绑定实例、期限、单次消费。账号、角色、主密钥引用与引导完成状态可恢复提交，成功后关闭正常引导。
- **旧部署**：随交付提供无需先升级旧环境的最小兼容迁移入口，只读读取旧库，复用可信 scrypt 实现验密，再执行已确认的指定账号迁移。不能先 git/pip 更新或下载执行 helper 再验密；安全库丢失、版本矛盾或 journal 未完成时停止，不能重新认作新安装。
- **管理员本机恢复**：本机控制权＋预先登记 TOTP 或高熵一次性恢复码，仅授予改密/换绑范围，消费证明、撤销和审计一致提交，不自动关闭 2FA。管理员恢复码与普通账号 MFA 备用码分开。
- 管理员恢复校验摘要、消费状态和实例版本另存受保护本机登记，明文只向管理员显示一次、要求独立保管。安全库损坏时经独立证明进入停服修复，重建认证版本并撤销旧会话；证明登记损坏或无法排除状态回退则停止人工恢复，不直接回滚旧凭据放行。
- 离线验密通过真正只读连接，不建目录/表、不 chmod、不补密钥。业务主密钥缺失但策略可核实时，2FA 关闭者可验密进入不依赖业务解密的修复；已开启者须有效第二因素/独立恢复证明。仍须恢复原主密钥，不生成替代品。
- 管理员角色不授予读取他人设备/会话内容。应用能管住正式管理入口，不能虚称抵御可任意改程序/磁盘的恶意系统管理员。

### C. 服务端可选 2FA

- 默认关闭；管理员在 `config/setup` 开启前须完成自己的绑定和恢复准备，开关修改明确确认、审计，并撤销/降限旧密码会话。关闭只停止要求动态码，不清除既有绑定。
- 采用常见验证器兼容的 TOTP，优先复用现有 `cryptography` 标准实现，不自写算法或无故新增密码库。秘密按账号/用途派生密钥加密，恢复码只存摘要。
- 绑定流程：密码认证→限时待绑定秘密→确认动态码→原子启用并由本人领取专属恢复码。服务端开启后，未绑定用户只有绑定权限，完成后才正常登录，不需管理员逐个配置；关闭时不强制普通用户绑定。
- 挑战绑定账号、实例、用途、安装/客户端及验证时账号/因素/策略版本；签发授权的同一事务重核版本并消费证明，改密/策略变化使旧挑战失效。持久化已用时间步、恢复码和失败计数，覆盖时钟偏差、并发重放与重启。
- CLI/Android 仅响应真实挑战；取消、切账号、重启、到期清理敏感输入，不将 OTP/密码放 `rememberSaveable` 或非秘密账号资料。绑定 URI/秘密/恢复码只在受保护交互中展示，审计脱敏扩展这些字段。
- 密码、邀请、重新建立设备密钥登录都不能绕过当前策略；正常 refresh 延续已满足因素的会话，不重复问码。换绑/恢复仅限对应范围，管理员改密不能自动取消用户 2FA。未知/损坏策略不能当“关闭”。

### D. 自动刷新、端点和注销

- 账号登录无需设备，账号无设备仍可登录并得到空列表；短期 access（沿用 15 分钟量级）＋轮换 refresh family/稳定 loginSessionId，不绑定 Android 配对。
- `client.py` 保留私有原子文件、权限/符号链接检查、TLS 和拒绝重定向，新增进程内合并与跨进程锁，防止 CLI/MCP 覆盖彼此新凭据。
- 稳定刷新操作 ID＋限时加密结果回执解决丢响应；重放匹配原摘要、账号、实例、客户端/family，不依赖重启前的内存 negotiationId。其他已用值重放撤 family，撤销/改密后旧回执不得返回可用凭据。Android journal 接到真实 Core 支持后才宣告重放能力。
- 在线退出撤当前 family；离线退出立即写本机屏障，所有本机客户端禁止继续使用/恢复，显示“本机已退出、远端撤销待同步”，联网后只撤销。不能宣称离线时已即时撤远端副本。
- 推送 owner 从短 Token 摘要改稳定登录授权关系，refresh 不改 route generation/ACK。接收者与来源设备分开：每份交付仍验证来源配对和 Android 选择的稳定路由，读取/ACK 验证接收者，不用动态路由重选推送来源。新登录不能接管旧端点，新手机不继承推送同意。

### E. 自动注册、四级路由和幂等

- Android 持久安装 ID 和按 Core/账号保存的 deviceId，登录/重连自动上报名称、必要版本/型号和公钥。复用既有身份须验证旧私钥 challenge 签名，不能只比较自报公钥/ID；重装、换密钥或换机建立新配对。
- 账号库增注册元数据/默认设备，保留旧 device_keys。先登记再返回实际配对代次，修复先 `_issue()` 后注册可能返回错误 generation 的顺序；在线继续用 `is_device_online()`，不用 lastSeen 冒充在线。
- 选择：显式目标→可信当前会话来源→有效默认→唯一在线。前三者离线保留目标；被撤销显式/来源应明确拒绝，不悄悄换设备；失效默认不参与。最终唯一性不按能力、名称、Agent 类型或排序偷偷缩小候选。
- 无设备、离线、多在线返回同一套结构化结果；歧义列表仅本人设备。能力查询返回本次所选设备及版本，但查询不等于请求已锁定，后续可显式使用该目标。
- 会话来源由 Core 绑定实例、账号、Agent、会话、回合/代次和来源设备；裸 sessionId、`agentName` 或桥令牌不证明来源。无来源的账号文本会话可正常工作，但不伪造设备身份/继承附件。
- 账号所有者可用 `oai devices --default <deviceId>`/清除选项管理默认；不自动把第一台设默认，不新增无关 Android 页面。
- 幂等先查账本再选路。键为账号＋稳定受验证调用范围＋幂等键，范围不含短 Token、新登录 session、目标设备或配对代次；独立 CLI 使用与账号验证绑定的持久客户端范围，正常重登/刷新保持，不能只填 ID 接管他人范围。
- 首次在同一账号事务保存摘要、requestId、deviceId、pairingGeneration、能力发布版本并入原队列；重复返回原目标，参数/显式目标不同则冲突。查询/取消/ACK/结果恢复继续验原归属及当前访问关系。重配对、断线或重试不改投，不重做未知结果，不增加 Core 能力许可。

### F. 极简 CLI、实例发现与 Agent

- 普通入口 `login/logout/devices/capabilities/invoke`；login 交互输入账号/密码，不需 `--device`。能力与调用支持可选设备，规则由 Core 决定。
- 管理入口 `account list/create <username>/delete <username>/passwd <username>`、`config/setup`。新账号只需用户名和必要密码，默认普通角色，不配置 Agent/设备。角色调整在已认证管理内，用户有必要的 MFA 自助入口。
- 保留 `serve/status/cancel/ack/endpoint/mcp/skill`；MCP 增本人设备列表和可选目标，禁止账号覆盖/管理员工具，不在后台工具中读取密码或 OTP，重认证返回清楚指引。
- 实例解析：显式选择→安装登记→已登录引用→受支持可信位置；多实例返回列表，不信任随意当前目录配置。跨机器首次无资料时，从可信非秘密连接信息或 `oai login --url`/交互一次提供地址，保存后不重复；不要求普通用户读取服务端秘密，配置引用用相对路径，不改变现有端口/TLS/明文警告默认。
- Agent 发现由插件/entry points 提供，限当前安装身份标准位置/已授权目录，不扫其他用户 HOME、不执行未知脚本。已支持 Agent 在首次授权安装中可自动接入；探测不等于成功，须真实安装/握手/注册，未连显示空状态。
- 统一注册验证稳定 instanceId、桥凭据/实例密钥、sessionScope 和真实能力；端口/别名/同名不能替换身份。关联现存原生身份须管理员或具双方关系证明的所有者首次确认并持久化，用户名相同不算证明。
- Hermes 由可信 Adapter 按稳定 Core 账号自动准备专属原生空间，不复制密码、不读其他历史；导入既有映射并保留别名/所有权冲突检查，不再手改每用户映射/allowlist。
- DSH/Codex 保留部署共享和最小环境，不能注入个人长期凭据；只有宿主能隔离时才接受受限回合委派，否则明确禁止继承个人设备身份，使用隔离 CLI/MCP。无 Gateway Agent 直接 Core 登录即可。
- 仓库内 Adapter/Gateway 使用统一规则；仓库外旧 Gateway（如外部 OpenClaw）只验证已知兼容并标明版本要求，不声称修改了外部项目。

### G. 安装、setup 与事务

- 已有部署必须在 git/pip 更新、插件/CLI/服务写入前经现有可信管理层认证。首次旧版兼容入口先验旧密码，不能下载新 helper 后直接交付密码；来源/版本需固定核验，同源附带摘要不算独立信任。
- 新装自动安装受支持平台缺失依赖、创建目录/密钥、Core/CLI/服务，安全引导首管理员并可启动。系统提权只安装依赖，不等于 Core 管理员；未知平台明确说明，不猜测包管理命令。
- setup 和 `oai setup` 先认证，再展示五项：网络设置、账号管理、Agent 接入、服务管理、退出。显示当前值/默认值，只有实际变化才提交，查看/退出不重写。正常开机/serve 只用已批准配置，不反复验密，也不能借启动引导管理员。
- `oai config`、helper、兼容 `gateway.admin`、服务、卸载及全局安全写入口共用管理验证。覆盖配对邀请/撤销、安全版本等旁路；用户自身签名退出/解绑保留原权限。删除、管理员改密、角色和重大变更确认实际影响，`--yes` 不能代替认证。
- 复用现有配置事务及锁，但 `configuration_lock()` 会建目录/chmod，须在成功鉴权后取得，再重核认证快照。journal 加操作者、范围、版本、操作 ID 和非秘密变更摘要，审计意图与最终结果对齐；失败认证仅可记安全失败/限流，不生成业务候选。
- 保留账号库、原密钥、设备、Agent/历史及原配置，不重复询问已有值，不静默轮换。多文件/代码/服务升级不是一个 SQLite 原子事务，使用分阶段 journal、恢复点与真实健康检查，分别报告回滚和部分完成。
- 授权到期不启动新变更，但允许已登记事务仅恢复 before-image 的限权回滚。无法安全回滚时停止并留现场，候选移动保留，不永久删除。
- 下载内容各放新空目录，脚本与输入分开，不从下载目录启动可能加载本地模块的解释器；不把秘密放下载目录。

## 迁移顺序

1. 只读盘点实例、账号、摘要、原密钥引用、安全版本和配置 journal。认证前不打开有初始化副作用的账号对象。
2. 旧部署先验证所选账号，再停止旧 Core、Adapter/管理工具等认证及写入者，核实停止并重核原摘要；新锁不能替代停止不遵守它的旧进程。
3. 准备完整一致 SQLite 快照和文件备份，按既有事务/journal 导入身份与角色、增加注册/刷新/账本/关联字段。全部约束、版本屏障及新认证入口就绪后才激活并恢复服务；中间状态不签发登录，不能部分账号走旧认证。
4. 旧 device-bound Token 保留原限制及到期，新增安全版本检查，不无提示扩为账号级；正常登录后才发新 family。若需一次过渡重登录清楚说明，以后换机/自然到期不反复配置。
5. 保留请求目标、配对、撤销、ACK、游标和未知结果；不因迁移重放敏感请求、不恢复旧快照抹去安全事件。端点导入原有限定关系，新手机不继承同意。
6. 更新封闭 Schema、错误码、能力协商、哈希/向量、随包资产和必要的 Core/Adapter 版本约束。旧端可兼容则保留原路径；不支持当前 2FA/安全模型的旧端明确要求升级，旧写入者受版本屏障拒绝。

## 验证与完成标准

规划阶段不执行测试。实施逐阶段跑针对性自动化，全部修改后跑 `npm run test:fast`，PR 前跑 `npm run test:pr`；协议变更显式执行 `npm test --prefix gateway-contract`、类型检查和对应向量。优先 CI/已有缓存，不反复本地全量构建，不加 `--no-daemon`；正式发布再跑 `test:full`。

| 验收组 | 必须覆盖 |
| --- | --- |
| 安装/管理 | 新装与并发引导、重复安装防绕过、旧账号指定验密；普通用户/桥令牌/设备令牌/root/过期或错实例授权拒绝；最后管理员并发保护；所有入口认证前无业务修改 |
| 2FA/恢复 | 默认关闭无交互回归；开启后 CLI/Android/管理一致；普通用户绑定及专属备用码、管理员独立恢复；错码/重放/时钟/并发/版本变化、邀请/设备密钥不绕过、身份库/密钥损坏失败关闭 |
| 登录/刷新 | 无设备登录、自动续期、并发/跨进程/丢响应/重启；在线撤销即时、离线退出本机即时屏障及联网撤销；秘密不出 argv/env/日志；旧 Token 不扩权 |
| 注册/路由 | 同安装重登/重连、同名/伪造 ID、公钥证明、重装/换机、实际 generation；四级顺序、离线不改投、失效默认、无设备/多在线、跨账号/伪造来源拒绝 |
| 请求/端点 | 换 Token/重登/重配对/重启重试不另投、不重复未知结果；原目标查询/取消/ACK；刷新端点连续、新 family 不接管、新手机不继承同意 |
| Agent/Android | 真实握手、未连接空态、首次确认/别名冲突、账号与共享范围；无 Gateway 直接调用；原登录/切号/退出/信任/附件/本地确认和执行恢复不降级 |
| 事务/升级 | 旧数据/原密钥保留、无变化不重写、锁竞争、磁盘/权限/替换/服务失败、中断恢复、到期回滚、审计与证明一致、旧写入者/降级拒绝 |

扩展 Core 的 transport、CLI/MCP、config、endpoints、pending requests、sessions、Hermes mapping 和 gateway_runtime 凭据/隔离/备份/审计测试；新增管理权限、安全迁移、MFA、账号刷新、路由与注册测试。保留并扩展 `tests/test_{install_script,core_setup_transaction,uninstall_script}.py`，覆盖真实 Shell main 认证顺序，不仅测试 helper。更新 `independent_core_contract.py`/`verify_distribution.py`，证明独立 wheel 无 Hermes 也能安全引导、登录及签名调用。可选 Hermes 使用 CI 固定 SDK、DSH 与 Android 对应模块独立验证，跳过不算通过。

真实验收先核对 Android CLI/ADB、隔离测试设备、合成账号、可信 TLS 和 APK 来源；用隔离 Core 验证登录/可选2FA/自动注册/CLI或MCP低风险调用/重连/歧义。不能直接运行旧 E2E 的 `pm clear` 或 argv 密码路径，不能清用户数据/读真实短信。安装 APK、切换真实账号或改权限另行确认；条件不足如实标未验证。

CI 用 concurrency 取消旧提交，先任务分支触发现有 CI 取得准入证据；需要等待时后台一次性监控，禁止前台 watch/循环查。独立复核尝试反证管理绕过、2FA 降级、跨账号/设备混淆、刷新/恢复重放和失败回滚，修复后重测。最终记录提交 SHA、命令、通过/失败/跳过、真机和未验收项，再创建面向 `dev` 的 PR，不自动合并。
