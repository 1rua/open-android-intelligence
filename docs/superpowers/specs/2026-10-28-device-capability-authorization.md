# 设备能力由 Android 统一授权的需求修订

日期：2026-10-28。状态：需求已接受；实现见 `feature/android-device-authority-20261028`，待 PR 合入 `dev` 与真机验收。
适用基线：`dev` 的 `e5c7f42a59262f404888858045aa975830dafb61`。
本修订覆盖旧模块化插件规格中的重复配对能力授权及 Gateway 账号能力开关；插件安装安全、
系统权限、数据隔离与敏感确认要求继续有效。架构决定见
[ADR-0059](../../adr/0059-android-is-the-sole-device-capability-authority.md)，证据与步骤见
[历史修复计划](../../reviews/2026-10-28-device-capability-authorization-repair-plan.zh-CN.md)，
分支实现、当前测试和未完成的真机验收见[实施记录](../../reviews/2026-10-28-device-capability-authorization-implementation.zh-CN.md)。

## 1. 用户问题与范围

用户已经安装并启用 Call Log Query、Notifications Query、SMS Query，界面仍提示
“当前 Gateway 账号未启用；请通过 Gateway 能力配置开启”。Hermes 已变为仅会话桥，
旧 setup 不能再作为设备能力授权入口。本次目标是消除这种重复授权与失效引导。

本修订涉及 Android 插件管理、能力状态发布、Core 能力发现和请求校验、各 Agent 接入说明
以及历史状态兼容。它不改变账号体系、设备身份、原生会话范围、Android 权限、通知应用
选择策略或屏幕操作风险等级。分支实现使用可选协商 HTTP 头，不改变 JSON Schema、Schema
哈希或 Gateway Protocol v2 版本。

## 2. 必须满足的规则

| 编号 | 需求 | 可观察验收结果 |
| --- | --- | --- |
| AUTH-01 | Android 是设备能力授权的唯一权威 | Core/Agent 配置不能覆盖手机本地拒绝，也不能要求额外许可才能调用手机已允许的能力 |
| AUTH-02 | 只有已安装且启用的插件，其能力默认开启 | 新启用插件无需 Gateway setup、账号能力开关或重复配对 grant；未安装或停用插件不能执行 |
| AUTH-03 | 保留手机本地显式关闭 | 本地关闭后，发现显示对应原因，请求不执行；重启、切账号、同步和升级不能默默开启 |
| AUTH-04 | 系统权限与数据范围独立检查 | 短信/通话记录权限、通知使用权、通知采集及应用白名单未满足时明确拒绝或返回符合本地策略的空数据 |
| AUTH-05 | 必要的敏感操作确认不能继承 | 发短信、屏幕控制等按原请求与当前设备状态确认，撤销、超时或参数变化后不执行 |
| AUTH-06 | Core 保留身份和协议校验 | 未认证、未配对、跨账号/设备、旧 generation、错误签名或 Schema、过期请求继续拒绝 |
| AUTH-07 | Core 不保留账号级设备能力否决 | 历史远端 `enabled[id]=false` 不影响新模型；状态以 Android 发布事实为准，未知状态不能伪造 READY |
| AUTH-08 | 所有 Agent 使用统一设备调用规则 | Hermes/DSH/第三方桥无需增加授权页；设备调用用明确的账号/设备凭据经 Core CLI/API/MCP，桥 Token 不能调用设备 |
| AUTH-09 | 状态与错误必须指出实际阻塞项 | 展示未安装、已停用、本地关闭、缺系统权限、需本地确认、服务不可用、待同步或连接不兼容；不引导用户找 Gateway 能力配置 |
| AUTH-10 | 旧授权与缓存迁移来源可识别 | 远端配置与本地用户决定分别迁移；旧快照失效后由 Android 重发，保留明确拒绝，不重建身份与密钥 |
| AUTH-11 | 取消重复授权不复活历史请求 | 已撤销、取消、终态、未知结果及幂等记录保留；旧队列不因策略变更自动执行或重发 |
| AUTH-12 | 本地权威覆盖执行与数据输出 | 在最终副作用及敏感结果外发前复核当前本地许可、请求绑定与有效代次；发生并发撤销时不能依赖进入请求时的检查 |

## 3. 状态与界面

插件启用、能力开关与可执行状态分别展示。启用并默认开启能力后仍可能因 Android 权限、
本地通知范围、屏幕许可或服务缺失而不可执行，界面必须指出下一步在手机上的实际操作。
能力发现与插件管理使用相同的阻塞原因，不以单一绿色“已启用”表示所有条件已经满足。

旧服务端返回的 `GATEWAY_DISABLED` 应诊断为旧授权模型或版本不兼容，指向升级与迁移说明，
不能把它翻译成“去 Gateway setup 开启”。旧字段 `gatewayEnabled` 的停止使用与兼容输出方式
属于后续协议审查；本需求不预先添加或改名任何 wire 状态枚举。

手机可保留针对已认证配对的本地细化限制，但它只能收紧手机决定，不能将“每次新配对重新
授权全部插件”恢复成默认使用门槛。新配对完成身份验证和设备绑定后，应按 Android 当前
已启用插件、本地能力默认值与明确限制发布状态；Core 不签发自己的第二份设备能力许可。

## 4. 迁移与兼容

- 旧服务端账号策略退出授权判定；缺配置、显式 true 和显式 false 都不能代替 Android 状态。
- Android 区分旧模型中“尚未创建 grant”与用户明确的本地撤销/关闭；对来源无法确认的记录
  不自动扩权，展示一次迁移复核入口，不能无限要求用户寻找不存在的远端设置。
- 保留已授予的 Android 系统权限事实、已设置的数据范围和所有明确本地拒绝；不自动请求
  系统授权，不扩大通知应用白名单，不为屏幕会话或高风险请求生成确认。
- 迁移后按配对重新发布可信快照并处理版本失效；本地缺少快照、失去连接或不兼容时明确不可用。
- 受限凭据仍绑定账号、设备和有效配对/状态版本；快照版本更新造成的预期失效应提示刷新凭据，
  不能通过跳过身份校验解决。
- 当前混合版本协商与迁移规则见实现记录。PR 合入和发布仍须按相应版本矩阵审核，旧外部
  Gateway/桥的兼容性和真机结果不能由本分支测试替代。

## 5. 验收边界

自动化验收至少覆盖 AUTH-01 至 AUTH-12，并以短信、通知、通话记录、屏幕读取/截图/控制
组成跨模块矩阵；API 31–36 的平台差异按相关模块验证。真实手机检查插件加载、系统权限
授予和撤销、通知监听与内容范围、屏幕授权和敏感确认。模拟器、单测、源码审查和真机证据
分别记录，不能以其中一个替代另一个。

Core 209 项与授权协商 4 项通过为主 Agent 最新报告的结果；Android 分模块测试及仍在运行的
App Fast 套件见[实施记录](../../reviews/2026-10-28-device-capability-authorization-implementation.zh-CN.md)。
