# 设置界面信息架构与文案优化

- 状态：已实施
- 日期：2026-10-24
- 范围：`apps/android/app` 设置主览与子页（`SettingsScreen.kt`、`SettingsCapabilityUi.kt`、`ConversationUiCapabilities.kt`、`NotificationCollectionScreen.kt`、`NotificationAppPicker.kt`、`PluginManagementScreen.kt`）

## 问题

改造前的设置主览把三类不同性质的内容混在同一张「设备能力与配对授权」卡里：

1. **能力授权**（把手机能力交给 Gateway）：短信读取、屏幕圈选；
2. **通知行为配置**（通知怎么提醒、怎么展示）：系统通知推送、原生会话气泡、Android 16 实时活动、通知采集范围；
3. **实现细节**：本机自增授权序号 `r{N}`、本机合成的配对标识。

带来的具体问题：

- 用户看不出「一共有哪些授权可以给」，也无法判断某一项到底是不是开关；
- 同一张卡里的条目行为不一致（有的跳转、有的开开关），点击前无法预期；
- 本机序号 `r{N}` 与 `pairingId` 对用户没有可执行意义，且容易被误读为 Gateway 下发的权威版本（裁决 D5 的原始约束是「不得让本地序号冒充网关权威值」，最稳妥的做法是不展示）；
- 「短信读取」直接跳转到插件管理，但文案没有说明这是「安装 + 授权」两步链路；
- 通知类条目分散在主览与授权子页两处，同一设置出现两个入口。

## 新的信息架构

主览按「一件事一张卡」重新分组：

| 分组 | 条目 | 性质 |
|---|---|---|
| 应用信息 | 应用更新 | 跳转 |
| 消息防抖 | 覆盖设置、等待时长、新消息延长 | 就地配置 |
| 外观与动效 | 外观、主题与动效 | 跳转子页 |
| 网关与账号 | Gateway 连接管理、连接加密状态 | 跳转 + 只读状态 |
| **设备权限授权** | 授权管理、插件管理 | 跳转子页 |
| **通知管理** | 系统通知推送、原生会话气泡、实时活动、通知读取范围 | 开关 + 系统设置跳转 + 子页 |
| 运行安全 | 开发者信任模式、安全策略说明 | 开关 + 子页 |
| 操作记录 | 授权与调用记录 | 子页 |
| 紧急与危险操作 | 紧急停止所有插件、解除设备配对 | 危险操作 |

关键变化：

1. **通知类设置单独立区**（通知管理），与「把能力授权给 Gateway」彻底分开；
2. **授权子页只做授权**：只保留短信读取与屏幕圈选，不再重复通知类条目，也不再展示本机序号与合成配对标识；
3. **主览只留一个授权入口**（授权管理），插件管理作为独立入口与授权并列，因为「装插件」和「给权限」是两步不同的事；
4. 删除主览「运行安全」区里与授权区重复的插件管理入口。

## 文案原则

1. **不出现内部术语**：`WASM`、`SPKI Pinned`、`manifest`、`outbox`、`attachment-status-v1`、`conversation-mirror-v1`、`LOCAL_GRANT_REQUIRED` 等一律不出现在用户可见文案中；
2. **陈述可执行事实**：说明「能不能用、为什么不能用、怎么才能用」，而不是罗列内部状态；
3. **保留必要的语义区分**：协商能力的「未声明」与「不支持」在界面上仍必须可区分（前者是这台网关可能支持，后者是明确拒绝），只是措辞改为用户能懂的说法；
4. **诚实降级不变**：能力未装配时仍明确说不可用，绝不渲染点了不生效的开关；
5. **不把内部机制简写成错误结论**：简化措辞时曾出现两处失真，已修正并补断言：
   - 网络安装填的是证书**公钥**的 SPKI 指纹，不是证书本身指纹（`SpkiPinning` 对 `publicKey.encoded` 取 SHA-256）；
   - 授权按账号分开保存，切换账号**不会**清空授权，切回原账号时授权仍然有效；真正清空授权的只有「主动解除配对」与「Gateway 报告授权变更」。

## 验证

- `:app:testFullDebugUnitTest` 全部通过；
- 新增断言：授权子页不再出现通知类条目、不再出现本机记账元数据、不得把切换账号写成需要重新授权；
- 既有「短信读取必须通向真实插件授权」的诚实性测试保持通过（改为先进入授权子页再点击）。
