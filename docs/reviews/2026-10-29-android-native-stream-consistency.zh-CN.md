# Android 原生流身份、版本与执行步骤消费

本步接续 `1d48909d`，只使用合成原生事件和内存 HTTP 传输，不读取真实账号或手机消息。

## 真实失败反馈

`AgentSessionClientTest` 的 29 项首轮结果为 25 项通过、4 项失败：

- 可靠 `eventId` 重放与较旧 `contentRevision` 仍被逐次追加，第一条真实消息正文被污染。
- 原生 generation ID 含 `/`、`?`、Unicode 和空格时，被路径段校验错误拒绝，合法查询不能发送。
- 可选工具执行快照没有解码，且其通知 eventId 会覆盖当前 Assistant 内容版本。
- 调试日志逐 delta 记录，20 个增量不是首帧、控制和终态三个边界。

修复后上述客户端类为 **29 项通过，0 失败，0 跳过**。相同正文、不同真实 messageId 分别保留；无可靠事件 ID 和版本的旧宿主继续原有追加语义。终态 done 可合法复用最后正文事件 ID，仍然必须确认终态，不能被增量去重跳过。

另运行 `WorkbenchNativeExecutionEventsTest` 得到 **4 项失败**，确认模型字段存在不等于真实工具过程已经进入时间线。该 UI 消费由独立修复步骤处理，不把客户端 29 项通过当作画面验收。

## 实现边界

- 请求查询值使用独立百分号编码，路径身份仍保留原安全校验，签名参数按规范排序。
- 文本 delta 只按可靠原生事件 ID 与同一真实消息的内容修订去重、拒旧。正文相似度、时间和 ID 前缀不参与判定。
- 工具快照通过既有 generation 帧承载，使用独立 executionRevision 和真实步骤 ID；无 Assistant messageId 的工具通知不改变当前正文版本。
- T6 诊断保持显式开关，只记录首个增量与控制、终态边界，不记录正文、工具参数或访问凭据。

补充的低版本 done 正文测试在旧逻辑下真实失败；修复后仍确认 completed 生命周期，但不使用较旧快照替换较新正文。另对仅有 eventId、无内容版本的有限去重账本增加预算边界：预算达到 4096 个身份后进入 OUTCOME_UNKNOWN 和原身份对账，不淘汰身份后继续追加。客户端现扩展为 **31 项通过**。

仓储新增两项真实回归首先均失败：观察错误没有 GET 恢复、工具步骤事件为空。实现把已受理后的观察错误与执行失败分开，以原 client/generation 查询，不重复 POST；工具步骤使用独立 ExecutionStepsUpdated 事件和执行修订，不生成伪 Assistant 消息。T1 仅在真正发起请求前记录一次，T6 保留首增量、控制和终态边界。

联合验证已得到客户端 **31 项通过**、六类 UI **76 项通过**。App 首次编译因 Kotlin 跨模块可空属性无法自动转换失败，改为先捕获局部值再判断后单独重跑仓储和所有者类；重跑为 **33 项通过、0 失败、0 跳过**，包含仓储 30 项和恢复所有者 3 项，Gradle `BUILD SUCCESSFUL in 1m 44s`。本步实际三部分共 **140 项通过、0 失败、0 跳过**；UI 76 项与客户端 31 项的结果来自前一轮已通过任务，未因 App 编译修正而无变更重复运行。所有验证日志保存在仓库忽略的工具目录，不提交测试产物。

增量协议仍只表达追加片段。本步拒绝已过时或重复的可靠事件，不宣称从任意乱序片段实时重建缺失正文，也不宣称支持实时非前缀编辑；完整内容最终通过原生历史补偿对齐。真实手机、模型和生产代理未在本步验收。
