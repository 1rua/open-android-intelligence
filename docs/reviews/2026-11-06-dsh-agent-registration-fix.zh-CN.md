# DSH 旧会话桥接入失败修复

日期：2026-11-06。开发基线：`00f146f14378e2f4c84d3ecacba415e8c1808a67`，提交前已快进整合 `dev@9506ecb5d5764131c93e85c53277c9730e24d5d4`。范围为 Core 管理入口和主仓 DSH Session Adapter 的升级流程，不修改 Android 设备协议、账号身份或原生会话历史。

## 已确认的故障

管理员在 `setup` 选择 DSH 候选并确认后，旧桥接端对正确令牌的 `GET /oai/session-adapter/v1/status` 返回 200、`online=true`，对 `POST /oai/session-adapter/v1/handshake` 返回 404、`NOT_FOUND`。错误令牌返回 401。故障来自缺少新注册握手接口，不能归因于服务未启动或令牌不匹配。

本机当时的 Core 为 `f85eda7668141fee4dc4ed4bf039cc2eaecb6054`，相关源码与远端 `dev` 一致。两处已安装的 `dsh-android-gateway 0.3.0` 源码均无 `/handshake`。隔离启动旧、新两个真实接口实现并调用 Core 握手方法后，旧实现复现失败，新实现通过实例身份、会话范围和 HMAC 验证。

协议在 `597fdd8c57bc` 引入，通过 `bad09803a459` 合入 `dev`；`d46ef603bf27` 新增自动发现，但 DSH 分支只准备令牌及候选配置。原安装代码中的 `_install_agents()` 未被安装主流程调用，且将宿主内部工具 `plugin_manager` 当作可执行程序，不能完成本机旧插件升级。

## 实现边界

- `agent_registration.py` 提供带稳定错误码和安全中文原因的握手异常。404、401/403、服务不可达、响应异常分别处理。响应正文、令牌及服务端错误内容不进入提示。严格身份、HMAC、会话隔离范围和管理授权检查继续生效。
- 自动发现遇到旧桥时提示进入 `setup` 处理，不再统一显示等待服务启动。交互式接入遇到旧 DSH 桥时返回可操作的升级流程；认证错误不触发升级。
- 只对默认本机 DSH 候选提供本机升级。通过已启用旧/新会话 bundle 的真实 profile 清单列出目标，由管理员明确确认一个。多个主目录不批量修改；远端、自定义端口和自定义前缀交给相应宿主管理。
- 安装前即时检查 Agent 管理权限，备份 profile 配置与可选锁文件，并同步备份文件及目录。通过 DSH 安装自带的官方插件管理 API 完成依赖安装和 bundle 选择，保留旧依赖及其他字段。安装失败、超时或激活失败时，在同一写锁内恢复原文件内容、权限及原锁文件缺失状态；失败版本另行保留，检测到并发写入或无法安全恢复时返回 `DSH_INSTALL_RECOVERY_REQUIRED`。旧 bundle 不与新 bundle 同时启用，避免插件 ID 与监听端口冲突。
- 文件更新后再次执行真实握手。宿主尚未重新加载时保持未注册，提示重新加载所选 profile 并回到菜单。不会仅凭安装命令成功或 `/status` 在线写入注册记录。
- 不自动重启 DSH，也不改动账号、主密钥、平台 ID、原生会话 ID 和历史。失败备份保留在 `runtime/dsh-adapter-backups/`，不永久删除旧插件或文件。

## 回归范围

真实 HTTP 用例覆盖旧 `/status` 在线但 `/handshake` 缺失、错误令牌、无效响应、超时和错误信息脱敏。管理菜单用例覆盖单个目标确认、多目标选择、取消升级、升级后有效握手注册、未重新加载时保持未注册、远端候选不修改本机，以及失败后仍可返回主菜单。

安装模块用例覆盖 profile 发现和显式筛选、授权检查、备份权限、官方 API 调用、保留其他配置和旧依赖、升级失败及重复执行。安装实现与运行中的宿主重载分别验证；本地隔离测试不代表用户当前 DSH 进程已经更新。

验证入口为 `npm run test:fast` 和 `npm run test:pr`；PR 触发的 CI 按提交 SHA 核对，通过后台回调检查结果和 review，不在会话前台等待远端构建。
