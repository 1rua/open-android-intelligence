## 修复范围

| 缺陷 | 修复后行为 | 关键回归 |
| --- | --- | --- |
| 01 流式中断 | SSE 读取只更新本轮最新消息快照；独立协程向 UI 发布。合并中间文本快照，但保留各真实消息、审批及终态，终态发布前排空待发布内容；约 33ms 更新一次文本画面 | UI 完全停止消费时，仍读完 4096 个文本片段、约 105 万字符；恢复后收到完整正文和完成事件 |
| 02 重复回复 | 客户端提交身份贯穿 Core/Hermes，SSE 与历史使用真实用户/助手消息 ID；临时草稿仅在明确对应时替换；不同真实助手 ID 不因同文或相同前缀而互相覆盖 | 多助手消息分流、实时/历史 ID 一致、跨轮同文、同轮同文、迟到流式草稿 |
| 03 历史乱序 | 接受秒/毫秒数字、带小数的秒时间和 ISO 时间；保留毫秒及偏移。缺失或非法日期使用稳定的未知值，不改成“现在”；同时间戳保留输入顺序 | 秒/毫秒/偏移时区精度断言；相同时间的用户/助手轮次顺序 |
| 04 正文误折叠 | 完成的可见正文关闭当前执行段；后来的工具/思考不能把它降级为叙述步骤。明确终态关闭工具输出光标 | 已完成回答前后接工具、后续独立思考、未闭合工具在终态不持续输出 |
| 05 文件夹失效 | 原生 Agent 的文件夹使用手机现有加密文档存储，按 profile/Gateway/账号/安装实例/Agent 隔离，revision 比较后原子写入 | 重建后保留、作用域隔离、过期 revision 拒写 |
| 06 排序无效 | 排序方式、自定义顺序、分组绑定与文件夹一起提交，界面明确提示本机保存 | 持久化及并发冲突；组织功能与远端删除能力分别判断 |
| 07 删除无效 | UI 分别核对删除、归档、重命名能力与在线状态；不支持的操作明确拒绝。仓储只在服务端 DELETE 成功后报告删除；本机偏好清理失败不推翻远端成功事实 | 无能力时不假成功、在线状态变化保留草稿、删除后真实历史不再存在 |
| 08 附件失败 | 纯附件/混排携带 attachmentIds 与 clientMessageId；Core 校验原账号/设备/配对，流式转入受认证 Hermes 附件端点并核对摘要，交给真实宿主 MessageEvent 的文件参数；校验、能力、协议、附件错误分别显示 | PNG 纯附件、docx+文字、字节与摘要、错误归属、上传期间撤销、重复提交身份 |

原生消息协议及存储边界详见[消息完整性说明](../architecture/2026-10-27-native-session-message-integrity.zh-CN.md)。文件夹和排序只在当前手机保存，不宣称跨手机同步；Core 仍不开放旧的组织管理端点。原生单条提交不宣称多消息批次能力，也不会把多条消息静默截为第一条。

最终自动化测试结果在本次 PR 的验证记录中列出。Core CI 新增会话领域、UI 全套测试和加密组织存储测试，避免只编译主程序而漏掉新增回归。数据层的历史 Gateway HTTP 兼容测试继续使用独立旧插件环境，不把旧插件装入 Core 独立运行验证环境。

## 证据边界与审查更正

- `Reading config.yaml...` 单独一行在当前 Markdown 解析器中并不会自动成为工具卡。因此工具光标修复针对真实工具块与残留流式状态，不把日志文本示例当作已复现根因。
- Hermes 原生 SDK 测试调用真实 SessionStore/SessionDB、HTTP 和 MessageEvent 文件路径，但模型处理器使用确定性测试回复；这不能证明某个远端模型支持所有文件格式。
- 本轮没有连接用户手机或切换生产服务。真实模型回复、实机长文本流、会话切换、图片/docx 发送应在同一部署版本上人工验收。
- 旧浮窗入口的目标身份尚不包含 Agent ID，不能把当前选中 Agent 猜作原消息所属 Agent。本轮主工作台原生会话修复不扩展该独立入口；其接线需要单独补齐通知/浮窗身份契约。
