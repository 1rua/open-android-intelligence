# 仅保留账号数据时的安装恢复（2026-11-06）

## 已复现的失败

将安装脚本通过 stdin 交给 Bash，目标目录只含 `runtime/accounts`，原脚本立即返回：

```text
[错误] 旧部署尚无安全迁移入口；请从可信检出运行 scripts/install.sh --dir <旧目录>。未更新旧部署。
```

Shell 拒绝没有本地 helper 的旧目录；即使从可信检出运行，Python 入口也要求目标内已有 `oai-core/pyproject.toml`，因此“保留数据后重装”没有完整入口。

## 修复行为

1. 从可信本地检出恢复，或将项目源码下载到旧目录之外的独立目录。若原虚拟环境也已丢失且系统 Python 缺少依赖，先在旧目录之外准备恢复环境，不改原虚拟环境。
2. 使用该源码内的管理入口验证旧身份库管理员；旧格式数据仍走原有密码验证及迁移检查。
3. 认证通过后补齐 Git 跟踪的程序文件。保留 `runtime`、现有配置与启动脚本，以及配置指定的账号、主密钥和身份库路径；发现其他已有文件冲突时保留原文件并停止。
4. 每个程序文件经临时文件原子写入，`oai-core/pyproject.toml` 最后发布，便于中断后重试。恢复后虚拟环境安装目标为持久目录中的 `./oai-core`，不依赖临时下载目录。

认证失败不会复制程序文件、创建目标虚拟环境或对原部署执行 pip；认证前的依赖准备仅限独立恢复环境。原账号、密钥与历史不按新安装重新创建。准备源码失败时，独立下载目录保留供复核。
