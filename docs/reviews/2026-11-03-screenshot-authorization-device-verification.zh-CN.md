# 屏幕截图与设备能力授权：真机验证清单

本文是 2026-11-03「无障碍按需截图 / 权限检查入口 / 能力阻塞判定」修复的**真机验收步骤**，
由具备设备的人在验收时逐步执行并记录。自动化测试覆盖决策逻辑与界面语义，
但无障碍截图、系统授权对话框与系统设置页的真实行为只能在设备上确认。

前置条件：

- 一台 Android 11+（API 30 及以上）设备；Android 14+ 才能完整验证投屏前台服务要求；
- 应用已安装且可登录（远程截图能力还需要已配对的 OAI Core）；
- 已安装并启用 `screen-capture` 插件（远程截图路径）；
- 每次记录：设备型号、Android 版本、应用版本、执行时间、实际结果。

## 1. 无障碍截图：不再反复系统确认

这是本次修复的核心目标：高频截图不应每次都弹系统确认。

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 1.1 | 系统设置 → 无障碍 → 找到本应用服务 → 开启 | 服务显示「已连接」；**不应**出现任何投屏确认框 |
| 1.2 | 通过 Agent 连续请求 10 次截图 | 每次都应返回新截图；**整个过程不应出现任何系统投屏确认框** |
| 1.3 | 检查能力状态（`oai capabilities` 或插件管理页） | `kernel.screen.capture` 为可用；`reason` 为空 |
| 1.4 | 记录 10 次截图的耗时 | 用于确认按需截图可行；若出现明显排队，记录数值 |

判定：1.2 中只要出现一次系统投屏确认框，即视为**未达成**核心目标。

## 2. 备用路径：MediaProjection 仍需明确同意

关闭无障碍服务后，截图应退回需要用户同意的投屏授权，且**不得**静默成功。

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 2.1 | 关闭本应用的无障碍服务 | 无障碍截图不可用 |
| 2.2 | 请求截图 | 失败，原因为「尚未授权」类；不得返回伪造截图 |
| 2.3 | 在插件管理页点「发起系统授权」 | 出现系统投屏确认框（不是跳设置页） |
| 2.4 | 拒绝授权 | 截图仍不可用；提示未获得授权；其他能力不受影响 |
| 2.5 | 再次点「发起系统授权」并同意 | 截图成功一次 |

## 3. 失败原因必须可区分

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 3.1 | 打开一个受保护界面（如密码输入页、支付页）后请求截图 | 提示「受系统保护无法截取」类，而非笼统失败 |
| 3.2 | 快速连续请求截图以触发系统限速 | 提示「频率限制，稍后重试」类，而非「设备不支持」 |
| 3.3 | 锁屏后请求截图 | 提示需要解锁 |
| 3.4 | 在系统设置中关闭无障碍服务后立即请求截图 | 提示「服务未连接」，引导去无障碍设置确认 |

关键判定：3.1–3.4 的四种提示必须**互不相同**，否则无法指导用户下一步。

## 4. 权限检查按钮：按声明动态生成

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 4.1 | 插件管理 → 短信插件 → 系统权限与后台任务 | 出现「短信读取」入口，动作为申请权限 |
| 4.2 | 通话记录插件同样操作 | 出现「通话记录读取」入口 |
| 4.3 | 屏幕读取/控制插件 | 出现「无障碍服务」入口，动作为「打开无障碍设置」 |
| 4.4 | 通知插件 | 出现「通知使用权」入口，动作为「打开通知使用权设置」 |
| 4.5 | 截图插件 | 出现「屏幕截图」入口，动作为「发起系统授权」（**不是**跳设置页） |
| 4.6 | 已授权的项再次查看 | 显示「已授权」且按钮禁用，点击不弹任何系统框 |
| 4.7 | 在系统设置里开启某权限后返回应用 | 状态自动更新为「已授权」；无需要手动刷新 |
| 4.8 | 在定制 ROM 上点某个入口 | 若系统无对应设置页，显示带具体路径的手动引导 |

## 5. 权限撤销与恢复

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 5.1 | 撤销短信权限后请求短信能力 | 明确拒绝，提示需要系统权限 |
| 5.2 | 重新授予后再次请求 | 恢复正常 |
| 5.3 | 关闭无障碍服务后查看能力状态 | 显示「服务未连接」（可恢复），**不得**显示成不可恢复 |
| 5.4 | 重新开启无障碍服务 | 能力恢复可用，状态自动更新 |
| 5.5 | 撤销截图授权后连续请求截图 | 每次均明确失败，不产生伪造或复用旧图 |

## 6. 能力阻塞判定（问题三）

| 步骤 | 观察项 | 期望结果 |
| --- | --- | --- |
| 6.1 | 从未申请过短信权限时的状态 | 显示「尚未申请授权」类，可一键申请 |
| 6.2 | 已拒绝过短信权限 | 显示「上次被拒绝」并引导去设置，不再重复弹框 |
| 6.3 | 插件被停用 | 显示插件未启用（可恢复） |
| 6.4 | 本机能力开关关闭 | 显示开关已关闭（可恢复） |
| 6.5 | 设备确实不支持某项能力 | 唯一显示为不可恢复的情形 |

判定：除 6.5 外，任何一项被长期显示成「不可恢复」都算**未通过**。

## 7. Core 统一能力接口不回归

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 7.1 | `oai capabilities` | 能力 ID、版本、schema、status、reason 结构不变 |
| 7.2 | 授权变更后再次查询 | 状态与 reason 反映最新系统状态 |
| 7.3 | 用不同 Agent/Gateway 调用 | 行为一致；实现中不出现特定 Agent 名称 |
