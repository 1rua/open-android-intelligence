# 本地会话镜像与控制器实施证据

日期：2026-10-14，更新于 2026-10-15。当前状态：账号夹具修复后的 App 84 个和受影响 UI 133 个测试均已通过；随后两个 SQLite P2 的 9 项新增存储范围已通过，Android 大消息复测与后续控制器 IO/hydration 接线待统一验证。前一轮通过不覆盖后续生产改动。本报告不表示 App 实机流程、完整 CI 或发布已经通过。本子任务未执行提交、推送或账号数据重置，契约发布等其他任务以各自证据为准。

## 已完成的行为

- 会话打开先读取手机已有的完整双向快照，再在后台更新服务器历史；有本地历史时，网络失败保留当前记录并提示同步失败。用户发送事实、消息身份和时间顺序继续保存，不通过等待计时器伪造服务器受理。
- 保存服务器完整分页历史时，按消息身份与单条正文修订合并最新本地事实。旧空页、同一消息的较低正文修订以及没有正文版本的旧页不能覆盖已完成的新回复；页面快照修订不充当单条正文修订。明确删除仍清除正文和对应私有附件引用。
- 未携带会话身份的正文或删除事件在进入控制器副作用之前拦截，不能借用当前屏幕的会话身份。非活动会话的合法附件事件在界面路由之前安排补存，更新其所属数据而不切换当前界面。
- 已落盘的消息附件引用同时作为可重建的保存意图；重启后从所有本地已知线程恢复补存，逐条入队并等待，已有原件先读本地。恢复不读取尚未同步过的服务器旧会话，明确删除的引用不再返回。
- 用户点击发送后，先持久保存原消息身份与内容，再归档已校验的附件原件，最后才提交消息请求。归档失败以 `LOCAL_SAVE_FAILED` 阻止消息 HTTP，保留草稿、原客户端消息编号和上传暂存；只有真实受理后才能释放暂存。原件自动补存、缩略图读取和公共下载分别执行；下载完成提示只来自真实导出端口返回，旧下载恢复失败的提醒不会被新下载成功提示覆盖。
- 恢复到发送结果未知的用户记录时，可以保存私有副本，但保留原上传暂存；只有持久受理事实或真实受理回执允许释放原件，手动下载也不改变发送结果。
- 用户明确重试时先查询原客户端消息编号；查询为已受理则收敛身份，不重新上传或发送。只有查询为未受理才从持久原件恢复上传源，并等待本次附件核验/上传任务真实完成。旧界面的 `VERIFIED` 状态不能提前放行；新附件编号写入原发送记录后再提交，客户端消息编号保持不变。普通草稿重发、未知结果恢复及历史附件批次使用这一规则；等待结束前再次检查已受理与删除事实。
- 删除或结束工作台会取消所属原件补存、归档和下载任务。删除清理使用会话与附件复合身份；迟到结果先检查删除屏障和账号范围，不能重新发布已删除内容。

## 持久化与兼容

`SqliteConversationRecords` 使用 Android 平台 SQLite 保存逐条加密的消息、发送单元和线程记录。正文采用 AES-GCM；认证附加数据绑定 scope 摘要、资源类型、查找键摘要与记录修订。数据库位于 `noBackupFilesDir`，账号范围由本地资料 ID、Gateway、稳定账号 ID 和安装实例共同决定。解密失败、未知格式和密文身份不匹配拒绝读取，不清空用户账号作为恢复手段。

事件的消息、正文/状态修订、删除屏障及对话游标在同一事务内提交。事务失败全部回退，游标保持可重放；完整基线的线程、历史与游标也一起提交。普通工作台检查点合并到 IO 写入，只有变化的记录更新密文；发送前和事件确认前等待关键提交。真实磁盘读取、服务器历史提交及媒体操作由可等待的 IO 端口执行；控制器同步读取改为只读已装载内存投影，不能以 SQLite 缓存热命中代替 IO 边界。

旧 `EncryptedDocuments` 镜像在一次事务内逐个读取认证和导入，所有记录与迁移标记一起提交，不同时持有全部旧正文；任一步失败全部回滚并保留旧文档与密钥。成功后旧目录移入迁移复核目录，生产旧密钥退役，旧写入路径停止使用。既有版本 1/2 的草稿、冻结发送身份、批次关系、明确删除和附件元数据继续恢复；原工作台中仅保存于最近会话的助手历史也纳入该线程记录。退出登录保留并锁定的语义继续有效，本地移除/解除配对的范围由 Runtime 负责执行。

控制器新增 `AwaitableWorkbenchPersistence`，提供本地历史读取、检查点/发送单元提交、提交确认及关闭存储；内存测试适配器保留原端口。控制器使用独立的标准 `SupervisorJob` 子作用域；`closeAndAwait()` 先提交关键状态，再冻结界面与新任务，取消并等待旧事件/发送/媒体/下载任务收尾，最后关闭原镜像实例。认证拒绝仍可使用同步 `close()` 立即锁定。关闭后的数据库对象拒绝写入，不能在另一个实例清理后重新创建旧数据。公共下载和历史原件的实际字节实现属于同一改动中的媒体适配器，不能仅用控制器夹具代替真实文件验证。

## 2026-10-15 SQLite 审查修复

[最终提交前独立审查](android-precommit-final-review.md) 的两个存储 P2 分别涉及单行查询窗口和全部历史常驻。主 Agent 的 [Android 14 大消息失败证据](android34-large-record-red.txt) 已实际保存并冷重开一条合法 3 MiB 消息，触发 `SQLiteBlobTooBigException`，失败位于原 `refreshRecords`；本轮修复在这条真实失败之后实施。

数据库表、记录包络、版本与 AAD 保持兼容。目标读取先查询不含 `payload` 的小型行头，再以每次 64 KiB 的 `substr` 查询取回同一事务快照中的密文，最后认证解密。没有扩大 `CursorWindow`、截断正文、恢复旧全文配额或删除旧库，因此已有大 BLOB 也可沿用同一读取路径。

存储构造只读取数据库版本和迁移标记，停止全表解密。SQLite 是数据权威；目标记录按需认证，近期明文使用 Android 平台 `LruCache`，默认计费预算为 `Runtime.maxMemory()/64`，约为堆上限的 1.56%，测试可注入 4096 字节。计费包含正文数组、查找键/逻辑键/行 ID 字符串和保守固定节点开销。单条正文超过缓存预算时仍正常读写，只是不放进缓存；淘汰、替换、事务失败、构造失败和关闭均零化缓存数组。该预算仅控制临时明文缓存，不淘汰持久历史，也不表示整个界面或 JVM 临时 JSON 对象都有相同内存上限。

`keys()` 在 SQL 层按 `resource_type` 排除内部消息、发送单元、线程和检查点正文，仅认证必要元索引；未打开的坏正文不会让枚举索引或打开无关线程失败，读取该目标时仍必须被 AAD 拒绝。事务失败直接清空缓存，回滚后的值由 SQLite 重新提供，取消原明文映射副本回滚。每次顶层访问核对 `PRAGMA data_version`，其他连接的提交或删除会失效本实例的热缓存；单条密文分块读取也在该事务内，避免混用两次修订。

同步 `read()` 即使缓存命中，仍需查询版本以维持跨实例一致性，因此属于磁盘端口。后续授权补充了控制器 IO 迁移：`atomsFor()` 只读内存投影；宿主已有 IO 构造边界先装载活动、批次和明确待恢复线程；新线程与基线重建通过 `hydrateSendAtoms()` 等待磁盘结果，`historyHydrated=false` 时继续显示加载状态并禁止提交，不把未读状态冒充空历史。

发送单元的读取、保存和写后最新读回由 `Mutex` 串行，结果回到控制器作用域后才安装投影；基线重建增加代数，等待期间发生重建的旧装载必须重新读取。既有单条正文/状态/删除修订规则继续保留。`loadSendAtomsOnIo()` 也供媒体侧受理判断使用，身份/预览同步函数只读投影。检查点的编码/保存、关键提交确认、本地首屏读取和关闭均显式切到独立存储调度器；生产默认 IO，旧纯内存夹具显式注入测试调度器以保留确定性。没有使用主线程 `runBlocking`，也没有弱化原首屏、未知发送或删除断言。本轮未改镜像文件，媒体方法的版本屏障由另一任务维护。

新增 `WorkbenchPersistenceThreadTest` 使用真实单线程 UI 执行器与 IO 线程，存储端口会记录并拒绝 UI 上的读取、保存和编码。其 [修复前真实失败](android-20261015-persistence-thread-red-runtime.txt) 是 `PERSISTENCE_ON_UI:read-atoms`，栈为 `atomsFor` → `openThread`；此前首轮媒体夹具编译失败未当作行为红。新回归还阻塞冷读并检查未恢复不发送、恢复后旧记录和新草稿、正常提交、删除及关闭；不使用固定等待。
