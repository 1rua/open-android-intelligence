# 用户行从乐观展示升级权威身份时的列表键

原息屏发送样本的输入只产生一次 Core 受理、一次 Adapter 输入、一份原生 transcript 和一次宿主执行；语义树只有一份用户节点，但连续硬件截图显示两份已完成气泡。帧日志进一步证实，旧 `local_<clientMessageId>` 行先显示完成，约 3.3ms 后真实 `messageId` 行开始组合；旧行和新行均提交了渲染帧。不能把该画面解释成后端重复发送。

原 `TimelineDisplayItem.Single.key` 直接跟随 `TimelineEntry.key`，会把同一逻辑输入的身份升级交给 LazyColumn 当作移除旧元素并插入新元素。生产列表带有退出和放置动画，旧退出图层是有实际时序支持的重复绘制路径。

修复在每个会话的 `TimelineDisplayModel` 中，按明确的 `clientMessageId` 记住无冲突用户行首次出现的列表展示键：

- 同一次输入的 local、真实消息 ID 和终态更新沿用同一个列表元素。
- `TimelineEntry.key` 仍是当前真实消息 ID，原对象、clientMessageId、generationId 和正文均不修改。
- 同一 client 同时对应多个真实用户行时，分别保留原键；别名与其他行或执行段冲突时退回本行原键，不合并消息。
- 无 client 的旧用户行、不同输入和助手多消息保留各自身份。缺失行和空列表清理展示记忆，按会话创建新模型。
- 动画参数未改变，没有关闭淡出、放置或上浮动画，也没有替换图形后端。

## 自动化与硬件边界

新增展示身份回归在旧实现真实失败：期望保留本地元素键，实际切换到真实消息键。修复后 5 项通过，覆盖终态早于权威 ID、不同输入同文、同 client 多真实 ID、无 client/多助手消息和别名冲突；另有 36 项既有执行展示通过。

Robolectric 的 `captureToImage()` 在等待重绘时超时；软件画布无法绘制 LazyColumn 退出 RenderNode。没有留下仅检查语义却声称覆盖像素的假回归，也没有将该测试设施限制当作产品失败。硬件像素复测显示，新用户气泡和新回复各一份，旧样本中的新用户气泡重复未重现；但顶部仍有不在语义树中的旧完成/复制图层，完整“没有旧图层”验收仍失败，滚动后残影消失。该失败没有改写为通过；后续只读可见项坐标诊断继续区分数据、动画层与模拟器图形缓存，不关闭动画或更换 GPU 取得通过。
