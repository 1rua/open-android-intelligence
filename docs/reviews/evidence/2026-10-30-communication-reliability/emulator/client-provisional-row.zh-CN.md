# 原稿合并丢失临时身份导致过渡双行

在用户行展示键修复后的只读布局诊断中，同一 clientMessageId 在一个有效列表状态里出现两份用户行：一份 `local_...`，另一份权威 `messageId`，两行均显示已完成。两行在 LazyColumn 的可见项里也同时存在；稍后本地行才移除。这是实际客户端过渡数据重复，不能再仅用“截图与语义不同”或模拟器 GPU 解释。

实际生产链为：本地持久 `LocalSendAtom` 合并成 `TimelineMessage` → 工作台映射成用户条目 → 原生身份去重。`mergeLocalSendAtoms` 以前没有设置 `localPlaceholder`，使本地生成行继承默认 `false`。投递状态已完成、权威消息 ID 尚未到达时，这一行被当作原生真实消息；为保护多个不同真实消息而设置的去重约束保留了它和后来到达的权威行。随后一行退出，触发可见残留。

## 修复与不变量

- 本地原稿合并保留显式来源。尚未获得权威身份的本地行仍是占位行，不能因投递状态达到 completed 就变成真实服务端身份。
- 与远端消息合并时保留远端现有来源和 generationId；不按消息 ID 的 `local_` 等前缀猜身份。
- 同一明确 client 身份出现占位和权威行时，优先权威行，然后再比较时间与内容。多个不同真实原生 ID 仍各自保留。
- 列表展示键保持前一项修复的稳定行为，消息 ID、clientMessageId、generationId 和原稿不被伪造或改写；动画没有关闭。

## 回归

新增回归直接经过生产 `mergeLocalSendAtoms` 再进入工作台原生身份去重，模拟本地完成先于权威 ID。旧实现真实失败：期望仅保留 `native-late-user`，实际同时输出 `local_cm_late_identity` 和 `native-late-user`。同时补充合并层测试，确认无权威 ID 的 completed 原稿仍标临时，以及名称形似本地 ID 的真实远端消息仍保留权威身份和 generationId。

合并层测试与真实工作台去重回归通过；原生多真实 ID、同文不同输入和已有展示身份矩阵继续保留。模拟器硬件像素复测及最终 Fast/PR 结果另行补齐。原始布局、截图及测试日志仅本地留存，本文件不包含用户正文、凭据或事件游标。

最终来源修复包 d7290694 的原模拟器有界像素和数据复测通过：息屏后两张独立截图及第三条新输入均无旧图层，35条布局快照没有同输入双行，三条消息各层只执行一次。旧失败保持原判定；详见 journey-25-provenance-fix.md。
