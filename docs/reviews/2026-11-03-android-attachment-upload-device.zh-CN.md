## 范围和结论

本次记录是 2026-11-03 在独立模拟器上对**基线**进行的局部验证，不是修复版验收，也不是生产环境验收。100 KB 和 4 MB 图片均完成选择、上传校验、发送并显示合成回复；50 MB 图片完成上传和服务端校验，但点击发送后界面显示 `OUTCOME_UNKNOWN`，没有观察到该次合成回复。三个样本在本次直连环境下均未复现卡在上传或校验的现象。

## 基线结果

下表每个样本仅一次。客户端写入、等待响应、Core 接收及 Core 校验分别依据各自进程的单调时钟计算，不能把客户端写入完成等同于服务端接收或校验完成。

| 样本 | 客户端内容写入 | 写完至 PUT 响应头 | Core 接收内容 | Core 写入耗时累计 | Core commit 校验 | 结果 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 100 KB | 8.47 ms | 63.57 ms | 46.73 ms | 0.73 ms | 1.25 ms | PUT 200；commit 200，`uploaded`；界面显示已核验，发送后可见合成回复 |
| 4 MB | 196.79 ms | 73.17 ms | 226.69 ms | 29.84 ms | 19.42 ms | PUT 200；commit 200，`uploaded`；界面显示已核验，发送后可见合成回复 |

Core 接收内容指内容请求进入处理后至全部字节读完的时间；写入累计为各数据块在 Core 写入函数内的耗时。按表中顺序，Core 完整 PUT 处理分别为 63.71 ms、254.11 ms、2073.83 ms；commit HTTP 处理分别为 22.06 ms、33.77 ms、274.02 ms。时间不相加为端到端总耗时，因为客户端和服务端工作可能并行。

100 KB 发送后，Android 日志中从会话请求开始到首个回复数据约 168.38 ms，到完成事件约 194.93 ms；4 MB 分别约 215.62 ms、236.27 ms。界面可见两轮合成回复，Adapter 记录了对应任务开始和完成。这不证明真实模型对图片的理解能力。50 MB 点击发送后，已保存的 Android 诊断中没有观察到第三次会话请求开始事件，Adapter 观察日志也仍只有前两次消息；但这不足以证明远端一定未接受，保持结果不明，不重复发送。Android CLI 的布局读取偶尔返回无法识别的响应，重试后恢复；4 MB 后的权限审核服务 503 发生在设备读取操作之前，不是 Core 或产品返回的上传错误。

50 MB 结果不明的本地消息 ID 为 `cm_ad76c489-0f6f-4e06-bdfa-d553f2cd7b74`，Core 附件 ID 为 `att_1224d970-b10b-43b6-a230-89fcc6c352d2`，创建时客户端附件 ID 为 `att_client_adft_d1dfb0801b9fcede`。Android 记录了 `send.clicked` 和本地气泡，但未见该消息 ID 的 `send.scheduled`、`send.dispatched` 或原生会话请求开始事件。后续只读收集的 AndroidRuntime/SQLite 环形日志已不覆盖该发送时段，未取得该次异常类别；不能据此断言没有 SQLite、内存或其他异常。现场草稿与原安装均保留，未点击重试。

源码中发送前既有本地持久化和归档，也存在会话恢复/身份歧义时返回 `OUTCOME_UNKNOWN` 的闸门；现有日志不能判定具体停在哪一步。合成 Adapter 的静态历史可能影响会话恢复，但这是待验证的夹具假设，不能据此认定根因，也不能推广为生产环境的 50 MB 发送失败。Adapter 观察日志只有前两次消息和任务完成记录；其数据库被运行中的服务锁定，未停止服务强行读取。
