本次修复把事件通道故障与登录、凭据、设备授权分开。普通 Access Token 过期先合并续期，再以新会话重新签名、连接并从已提交游标补事件；网络错误保留登录资料、工作台与草稿。只有刷新凭据明确失效、权威撤销事件或不可恢复的认证条件才要求重新认证。

根因有三处。第一，SSE/WS 的 401 原先直接变成 `EventSessionRejectedException`，运行时随即拆除会话并显示“授权冻结”，没有调用已有刷新入口。第二，手动刷新会重建整个工作台，且多个 HTTP/事件客户端各自保有不可变的旧 Token；简单增加重试会造成并发轮换和在途任务中断。第三，两个固定版本的 Gateway 都会立即作废旧 Refresh Credential，却没有保存可安全重放的轮换结果；提交成功后响应丢失会让后续请求触发 `REFRESH_REUSED` 撤销。

Android 共用 `GatewaySessionRenewal` 管理完整会话快照、单飞续期及关闭屏障。HTTP 请求最多续期重放一次，保留业务请求 ID/幂等键，重新生成签名、时间和 nonce。事件恢复额度同时约束多个客户端与界面重订阅，只有该客户端当前会话的完整心跳或业务事件才能恢复额度；持续认证拒绝暂停通道，不冻结设备授权。现有心跳静默超时、指数退避、游标去重和快照恢复继续使用。

传输层还记录已失败的会话快照，重订阅或网络回调不会再次发送同一失效 Token；发布新快照后才允许重新尝试。工作台对认证恢复耗尽和明确暂停状态停止定时重订阅，普通网络异常仍自动恢复。新增失败测试分别复现了重复订阅多发两次认证请求，以及一分钟内重订阅 61 次的缺陷。网络回调和手动续期恢复主工作台时回到主线程，并核对控制器身份，避免并发建立订阅或唤醒旧账号。

刷新操作采用写前日志：先保存稳定操作 ID 和凭据摘要，再发送；成功后通过 `AtomicFile` 保存 Keystore 加密的新凭据，随后保存会话绑定、清理日志并发布新快照。进程在任一步骤退出都能识别已提交状态。已收到但保存失败的结果先重试本地保存。撤销、解绑、切换账号和退出与续期收尾串行，避免旧异步保存重新写回已经撤销的凭据。

Gateway 源码位于独立仓库，因此完整服务端改动以 [OpenClaw 补丁](../../gateway-contract/patches/session-recovery/openclaw.patch) 和 [Hermes 补丁](../../gateway-contract/patches/session-recovery/hermes.patch) 交付，附原生回归测试与固定版本检查工具，未改写远端 pin 为未发布的 SHA。补丁以协商 header 声明可选能力，在同一 SQLite 事务中轮换并加密保存结果；不同操作重复使用旧凭据仍撤销，撤销后的结果不得重放。部署步骤见 [补丁说明](../../gateway-contract/patches/session-recovery/README.zh-CN.md)。旧 Gateway 的正常 401 仍可自动续期，但它无法恢复“轮换已提交、结果丢失”的未知结果；客户端保留资料并停止盲目重发，完整保证需要部署对应服务端补丁。

后台仍只为用户发起的在途任务使用 `dataSync` 前台服务。持久化资格允许系统合法重建服务，服务先前台化再恢复账号；60 秒恢复租约不因重复重建或过期后到达的旧 Intent/事件而延长。复用已有当前生成任务查询确认选中会话的真实工作，不能以缓存中的“处理中”续租。任务完成、主动退出、解绑、启动被拒和系统超时清除资格。网络切换唤醒原有连接所有者，不从任意后台入口启动新服务。
