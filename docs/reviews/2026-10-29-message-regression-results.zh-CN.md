## 问题与共享故障路径

| 问题 | 已运行的失败反馈及修改 | 证据边界 |
| --- | --- | --- |
| BUG-01 重复消息与状态 | 原生路径在 HTTP 尚挂起时发布本地受理，真实 ID 到达后再次绑定；现仅真实回执推进身份，显式区分本地占位与真实消息。同文但不同原生 ID 保留。慢消费者丢弃身份帧路径亦已复现并修复 | 合成 HTTP、持久事件和 Android 仓储/控制器；真实用户会话未访问 |
| BUG-02 点击后气泡延迟 | 本地保存挂起时原输入仍留在编辑框；首会话创建又会清空气泡；编辑下一条草稿还会撤回等待附件的冻结消息。相应用例先失败后通过；冻结身份与气泡在同次状态更新建立，远端请求仍等待可靠记录 | 142 项 Android 第一阶段联合回归中的直接用例；不等同真机点击到屏幕时间测量 |
| BUG-03 断流后卡住 | 内存事件观察不重放已错过输出，初始健康为 LIVE，Android 未调用指定回执。现反映真实连接阶段，断流后按原 client/generation GET 回执并读取原生历史；固定 Agent 订阅、恢复所有者及队列路由 | SSE EOF、两层 HTTP 断开、切 Agent、旧回执和历史补偿已自动化；厂商后台策略仍待真机 |
| BUG-04 长期未知 | 活动 generation 为空不能证明完成。已新增可协商的持久终态查询、生命周期 revision 和最长 25 秒条件等待；Android 不自动重发原请求 | 完成后的指定回执、离线宿主可读、错误身份拒绝；真实宿主停止且没有终态证据时继续未知 |
| BUG-05 断网影响宿主 | 手机与桥接观察连接关闭不能取消已受理宿主任务；真实 HTTP 测试断开后只分派一次且仍完成。恢复提示生成方已追到 Hermes ledger / resume_pending | 不按正文删除或改写已有 System note；真正宿主进程死亡的恢复能力不能由手机观察测试替代 |
| BUG-06 工具卡错位 | 移除正文关键词推断；原生 call/result ID 与 generation 形成独立步骤事实，一轮一张卡，回答保留真实 ID。公开 pre/post 回调提供实时事实，缺失结果为未知，参数结果清理按原账号与会话范围 | 服务端固定 SDK 含执行中快照、取消、缺回调、跨库提交失败及删除隔离；Android 实时消费后续步骤另记 |
| BUG-07 卡顿与长帧 | 1024 项观察队列无差别丢旧帧已复现；改用持久记录每批 128 项顺序读取及事件唤醒。约 600 KB 最终行触发网络库默认上限已复现，改为有界 8 MiB 并保留明确超限错误 | 证明传输可靠性，不宣称已优化真实手机 Markdown/Compose 帧率；诊断不按 token 输出正文日志 |

几个问题共享原生入口迁移后的身份、状态和恢复契约缺口。测试没有证明所有用户现象均由同一原因产生。快速队列交接窗口在强化调度测试中仍未复现，其单所有者交接调整属于设计保护，不作为已复现根因。

## 架构、数据与验收边界

继续使用 Android → OAI Core → Hermes Session Adapter → Hermes Agent。Core 仍是通用会话、身份与设备授权入口；Hermes 专有回调、原生历史与执行步骤保留在适配器。没有创建第二份模型对话历史，没有读取或修复用户真实 SessionDB，没有变更账号、密钥或平台身份。

本次 SDK 测试使用隔离 Home、临时数据库及合成处理器，不调用真实模型或真实危险工具。未进行用户手机、厂商后台策略、生产代理、真实模型、跨机器阶段时延或宿主真实进程死亡验收。只有出现明确执行终态才能结束未知状态；观察断开不等同执行失败。
