# PR #14 Codex Review 复核与修复

后续已将配套实现同步到独立插件仓，并更新主仓固定引用与 CI，见[插件同步记录](2026-10-19-gateway-plugin-sync.zh-CN.md)。以下保留评审修复当轮的补丁和测试记录。

复核对象为 `34a16aba68f70eeb911cb0f5b8b27f10b6c4580a` 上的五条代码评审意见。上一轮本地完整检查和 GitHub CI 均已通过，但测试通过不代表这些恢复与并发边界没有缺陷。

| 评审意见 | 判断与处理 |
| --- | --- |
| [P1：不能按大小比较快照版本](https://github.com/1rua/open-android-intelligence/pull/14#discussion_r4313829687) | 成立。两个宿主的列表版本来自内容哈希，只能判断相等。Controller 和加密镜像改用本地读取序号、账号范围和管理操作屏障拦截旧结果；分页内仍要求快照 token 相等。重启恢复和旧检查点也不能把列表回滚。 |
| [P1：管理操作重试必须保留请求 ID](https://github.com/1rua/open-android-intelligence/pull/14#discussion_r4313829698) | 成立。发送前持久化原始请求 ID 与完整归档/删除意图，主界面和气泡共用账号范围的操作存储。未知结果、取消、认证失败和服务端错误保留原操作；确认结果与镜像变更一起提交。相反操作须先恢复旧操作，首次读取列表也恢复待确认操作。 |
| [P1：非权威列表不能证明通知目标已删除](https://github.com/1rua/open-android-intelligence/pull/14#discussion_r4313829709) | 补充防御性校验。当前 Runtime 的通知路径使用直连远端的 `workbenchRepository`，并未进入评审描述的镜像 I/O 回退，因此不能声称复现了该运行路径。不过删除边界此前确实丢弃权威性信息，现在要求完整且权威的 `ConversationPage`，保留账号及目标修订保护。 |
| [P2：CAS 冲突后保留原组织操作](https://github.com/1rua/open-android-intelligence/pull/14#discussion_r4313829718) | 成立。仅对明确的 `ORGANIZATION_CONFLICT` 最多尝试三次，每次读取最新状态并重新应用同一操作，保留其它设备的无关修改。取消、作用域切换、其它错误或耗尽次数时不继续写入。 |
| [P2：升级前的原生删除缺少识别依据](https://github.com/1rua/open-android-intelligence/pull/14#discussion_r4313829727) | OpenClaw 成立。利用已有原生历史身份、匹配路由的原生检查点和确已交付的消息收据识别升级前已建立的会话，持久化删除屏障；只有绑定、尚未交付或交付前失败的会话仍保留。Hermes 已区分未建立的会话与已附着的原生 SessionDB 身份，补充相同升级场景的回归。 |

真实原生存储故障注入还确认：Hermes 的通用未知结果记录会阻止同 ID 再次进入管理操作，需仅对匹配可信待确认记录的归档/删除恢复该流程；其它未知操作继续受原有保护。两端已满足目标状态的归档不应再次调用原生写入。新增客户端持久化路径也要防止镜像包装层晚到的重复写覆盖另一端较新的确认状态。

OpenClaw 全量回归发现，历史删除识别还必须区分可信原生路由：一个会话合法切换到尚未建立的新 `storePath/sessionKey` 时，旧路由的交付收据不能证明新路由已经被删除。原生存在记录现在绑定具体路由；切换绑定时隔离旧证据，重新建立原生会话后才恢复删除识别。已删除或待确认的会话仍拒绝重新绑定，不能借此绕过删除或待确认屏障。原有宿主回合边界测试保持不变，并补充重启及重新建立后删除的回归。
