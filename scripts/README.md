# Core 安装与配置向导说明

`install.sh` 负责交互式安装或更新 OAI Core 服务端；`setup.sh` 和 `oai setup` 负责日常管理已有部署（改端口、管账号、连 AI 助手、启停后台服务与开启两步验证）。在仓库根目录或已安装目录中运行：

```sh
./scripts/install.sh
./scripts/setup.sh
# 或在已安装服务端本机直接运行快捷命令：
oai setup
```

脚本支持 `-h` / `--help` 查看用法，可通过 `--dir <路径>`（或环境变量 `OAI_DIR`）指定安装目录（默认为 `~/.oai-core`）。终端输出会根据当前 TTY 与 `NO_COLOR` 环境变量自动适配彩色卡片边框与进度提示。

## 四步交互式安装流程

全新安装时，`install.sh` → `installer.py` → `scripts_runtime.py` 会按 4 个清晰步骤引导完成部署：

1. **步骤 1/4 · 准备 Python 运行环境**：检查系统 `Python 3.11+`（含 `venv`）与 `Git`；若缺失则在确认后自动调用系统包管理器安装，并在安装目录内创建独立虚拟环境 `.venv`。
2. **步骤 2/4 · 创建首个管理员**：设置管理员用户名与登录密码（后续手机 App 登录配对与后台管理均使用该账号）。
3. **步骤 3/4 · 备份管理员应急恢复码**：屏幕会展示仅显示一次的独立管理员本机恢复码，确认保存后继续。
4. **步骤 4/4 · 后台自启与服务设置**：自动生成初始配置（默认监听 `0.0.0.0:11451`）、安装全局快捷命令 `~/.local/bin/oai`、扫描并尝试自动连接本机已安装的 AI 助手（Hermes、DSH），随后询问是否配置开机自启服务，并展示汇总卡片。

如果目标目录已有安装记录，再次运行 `install.sh` 会先验证现有管理员账号与密码，通过后再更新组件，原有配置、密钥与账号数据保持不变。

## 交互确认与方向键选择规范

安装脚本（`install.sh`、`installer.py`、`scripts_runtime.py`）、配置向导（`setup.sh`、`oai setup`）与卸载脚本（`uninstall.sh`）的所有菜单与操作确认均支持**键盘 `↑` / `↓` 方向键实时高亮切换选项（`❯`）并按回车键确认**，同时完全兼容直接输入编号/字母后回车，以及原有的确认口令（如 `bootstrap`、`SAVED`、`STOP`、`restart`、`register`、`enable`/`disable` 或目标 Agent 标识）：
- **方向键交互选择**：在主菜单、账号管理、Agent 候选列表、DSH Profile 选择、后台服务管理、两步验证管理以及各步骤的“是/否”确认中，均可直接按 `↑` / `↓` 切换高亮项并按回车执行，无需手动输入数字或英文口令。
- **系统依赖与源码拉取**：`install.sh` 在缺少系统依赖或检出源码时，默认高亮 `1. 是，继续执行 (Yes)`，直接按回车即为同意，也可按 `↓` 切换到 `2. 否，取消退出 (No)` 或输入 `y`/`n`。
- **全新安装与恢复码登记**：初始化 Python 环境、确认创建首个管理员账号、确认已保存恢复码均支持 `↑` / `↓` 切换或直接回车（输入 `y`）快速完成。
- **服务管理、Agent 接入与 2FA 开关**：`oai setup` 中的服务启停/重启、确认连接 Agent、重新生成恢复码及开启/关闭 2FA 均支持 `↑` / `↓` 选择或直接回车确认；输入无效选项或错误端口时会友好提示并留在当前菜单，不会直接崩溃退出。
- **卸载确认**：`uninstall.sh` 交互模式提示 `确认卸载？(y/n) [y]`（`--purge` 模式下亦兼容输入 `y` 或 `PURGE`），非交互环境可通过 `--yes` 跳过交互提示。
- **高风险账号操作**：删除账号、重置他人密码依然要求输入目标用户名确认，防止误删或误重置。

旧版本部署更新前须指定现有账号、验证原密码并确认停止旧 Core、Adapter 和其他写入进程；所选账号将升级为管理员，其余旧账号保持为普通用户，原有聊天与设备记录完整保留。

## 设置面板（`oai setup` / `setup.sh`）

验证管理员身份后进入 5 项交互式主菜单：
1. **网络设置**：修改监听地址（`0.0.0.0` 允许局域网手机连接，`127.0.0.1` 仅限本机）与端口，直接回车保持原值。
2. **账号管理**：查看账号列表（标注管理员/普通用户）、创建新账号、修改/重置密码、删除账号。
3. **Agent 接入**：自动发现本机已安装的 Hermes、DSH 等 AI 助手（标注 `按账号独立会话` 或 `全局共享会话`），确认后执行真实握手连接。
   - 若本机 Hermes 或 DSH 尚未安装连接插件（会话适配器）或版本过旧，向导会自动提示是否在所选目录或运行配置（profile）中一键安装/更新，并自动备份原配置（备份分别位于 `runtime/hermes-adapter-backups/` 与 `runtime/dsh-adapter-backups/`）。
   - 若插件更新后对应 AI 助手仍在运行旧进程，会提示重启或重新加载该助手服务后再试。详情见 [Hermes 会话适配器说明](../integrations/hermes-session-adapter/README.md) 与 [DSH 会话适配器说明](../integrations/dsh-session-adapter/README.md)。
4. **服务管理**：查看当前用户的后台服务状态，一键启动、停止或重启服务。
5. **两步验证 (`2fa`)**：在主菜单通过 `↑` / `↓` 方向键选中 `2fa. 两步验证 (2FA)`（或直接输入 `2fa`）可绑定手机验证器（TOTP）、重新生成管理员恢复码、开启或关闭两步验证。

## 二次验证和管理员恢复

服务端 2FA 默认关闭。需要启用时，在 `oai setup` 输入 `2fa`，先绑定管理员验证器并分别保存账号备用码和独立管理员恢复码，再确认开启；策略变更会使原会话失效。开启后，CLI、Android 和本机管理按提示提供验证码；正常会话续期无需重复输入。

忘记管理员密码时，在服务端本机运行 `oai recover ADMIN_USERNAME`，按提示输入预先登记的**独立管理员本机恢复码**和新密码，并确认目标账号。此操作撤销旧会话，不会关闭 2FA；普通账号的 MFA 备用码不能代替它。密码、验证码、恢复码不要放进命令参数、环境变量或日志。如果恢复登记损坏、原主密钥缺失或状态无法确认，停止操作并保留现场人工恢复，不要重新初始化。

删除账号或更改密码前先确认目标和会话影响；系统应阻止删除或降权最后一个可用管理员。更多日常命令和设备选择见 [Core 使用说明](../oai-core/README.md)。

## 保存与保留

配置保存前先认证并核对监听地址、端口、原配置和主密钥。静态配置检查不能证明远端在线，也不保证输入的主机名能在本机绑定；新 Agent 注册需要单独验证真实握手。

保存包含 `core.json`、`start-core.sh`、适配器 Token 文件及已发现的 Hermes、DSH 环境文件。候选文件先准备完成，再检查备份 SHA-256，写入恢复 journal，逐个原子替换；文件内容和 POSIX 目录均执行 `fsync`。Windows 无目录 `fsync` 接口，其断电持久性不作同等保证。

- 原配置路径、主密钥、账号密码和历史保留；不会重置旧账号密码或生成替代主密钥。
- 新账号在隔离目录准备，提交时才移入目标位置。失败候选保留供复核，不永久删除。
- 空选择表示本次不新增 Agent，已有配置仍保留；发现候选不等于已连接。旧版 Hermes 映射需要保留并核对，自动专属空间仍在集成，尚未验收。
- 原环境或凭据文件不可读时拒绝保存，不以空内容覆盖。
- 已有 DSH 凭据按 YAML 结构更新，保留其他引用；已有 YAML 需配置 Python 环境安装 `PyYAML`。缺依赖时显示 `DSH_YAML_PARSER_REQUIRED`，保留原文件，可在对应环境执行 `python -m pip install PyYAML==6.0.3` 后重试。空凭据文件无需增加 Core 的强制运行时依赖。

备份、候选文件和 journal 可能包含私密配置，仅供部署所有者访问，不应提交 Git 或公开传输。不要将桥令牌与账号密码写进日志；应核对配置事务状态、文件摘要与权限，不能以进程退出码代替实际保存结果。

## 失败恢复

恢复前先停止其他配置写入者，并验证同一部署的管理员身份。遇到未完成事务时保留 journal 和备份；重新运行安装入口可在获得授权后检查并恢复配置事务。确认恢复完成后再启动服务。

- 当前状态：`runtime/configuration-journal.json`。
- 每次事务的备份、候选和 journal 副本：`runtime/configuration-backups/<事务ID>/`。
- 原 JSON 另保留为 `runtime/configuration-backups/core-<事务ID>.json`。
- 正在提交的状态为 `applying`，结束状态为 `committed` 或 `rolled_back`。新生成的 `start-core.sh` 遇到未完成或损坏的 journal 会拒绝启动。

正常异常会自动恢复旧文件的内容与权限。中断后重跑先核对全部备份与当前文件 SHA-256，并在每次实际替换前再次检查当前目标，再恢复；新文件或新账号目录通过移动保留，不永久删除。恢复自身也可重跑。所有写入者仍须遵守同一配置锁；不参与锁协议的外部程序可能在最后一次检查和原子替换之间写入，因此必须先停止其他配置写入者。

如果备份损坏、文件被其他写入者修改，或权限故障阻止回滚，脚本停止并保留 journal。此时请继续停止服务，检查 journal 指向的备份与候选、恢复权限，并核对文件摘要；不要直接删除 journal、替换主密钥或重新创建旧账号。确认备份完整后重跑保存；无法确认时保留现场人工恢复。手动执行 `oai serve` 会绕过启动脚本检查，恢复完成前请勿使用。

旧版本启动脚本在首次升级提交前还没有 journal 检查，因此停止服务及其他写入者是升级前提。事务保证可恢复，不宣称多个文件对运行中的读者同时可见。

## 完成状态

- 返回 `0`：配置及本次请求的安装流程完成。
- 返回 `1` 或其他保存错误：配置未提交完成；旧文件已恢复，或 journal 记录了待恢复状态。不会打印保存成功。
- 返回 `2`：配置已提交，但可选 skill、插件或系统集成未全部完成；明确提示“部分完成”，按提示重试，不会声称完整向导全部完成。

可选 skill 同步不会删除旧目录；插件安装、CLI 和自启动步骤在配置提交后执行，其失败不回滚已经提交的配置。

## 配置回归

使用已有 Python 环境，针对性运行：

```sh
PYTHONPATH=oai-core/src:integrations/hermes-session-adapter/src \
  python -m pytest tests/test_core_setup_transaction.py \
  tests/test_install_script.py oai-core/tests/test_core_config.py -q -rs
```

`test_core_setup_transaction.py` 覆盖真实 Shell 保存入口、文件替换与加载故障、中断恢复、备份损坏、并发写入拒绝、畸形配置和保留语义。测试使用合成账号和隔离宿主目录。不能创建符号链接的文件系统会优先使用现有的无害解释器符号链接，并断言系统返回 `ELOOP`，证明拒绝发生在读取目标内容之前；两种真实链接均不可用时才明确报告跳过。文件权限测试通过不能替代符号链接实测。
